# 上传器与 Pro 健康类别一致性

Pro 下载器使用三份 CSV 核对身份、佩戴时段和下载资格；健康类别沿用样本试验台账的“数据分类”。上传器已给出 review（待核对）的记录不会被 Pro 再按“监测目的”改成产犊或孕晚期。旧 CSV 未提供明确分类时，才保留监测目的兼容映射。派包完整性核验使用同一 CsvPlan。

分类条数、有效样本条数和 JSON 文件数是三种计数。台账一条佩戴记录可跨多日，并产生多段 Motion、PPG 和 Temp JSON；不能按文件数或“设备×日期”的目录数计算产犊样本量。分类为产犊不等于已经通过下载门槛：仍要求五项填写完整、九轴和温度有效、产犊开始/结束是有效时间且结束晚于开始。明确 calving 分类即使保留原始孕后期监测目的，也必须满足真实产犊时间要求。

本地历史原始数据需要按真实采集时间、设备号及牛号回溯到对应佩戴记录，不能凭当前文件夹名推定健康类别。重复内容、超出佩戴区间、身份冲突和已有人工作业记录必须分开核查；不会为凑齐上传器条数而生成、删除或改写传感器值。CSV 刷新与文件归档不等于对历史标签、数据集或模型做了新的有效性认证。

本次回归覆盖：review 阻止查询与保存、CSV 后续补全后重新授权、完整产犊区间沿用上传器 calving 分类、明确 calving 不能用“/”绕过时间检查，以及已有下载与派包测试。
