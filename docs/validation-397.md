# 3.9.7 原始录像归类验证

日期：2026-09-18。功能修改在 3.9.6 最终源码上完成，真实片段在独立验收牧场运行。

## 实际速度与画面核对

选用正在处理的真实录像的已提取码流，前 60 秒，2560×1440、H.265、25 fps、全范围像素及 PCM 音频。三组均输出 H.264/AAC，并完整解码与核对时间轴。

| 编码器 | 转换与校验合计 | MP4 字节数 | 输出时长 |
| --- | ---: | ---: | ---: |
| CPU libx264 veryfast CRF 23 | 19.682 秒 | 51,877,876 | 60,000 ms |
| NVIDIA NVENC p4 CQ 23 | 15.922 秒 | 124,489,520 | 59,961 ms |
| Intel QSV veryfast quality 23 | 14.737 秒 | 83,977,395 | 60,000 ms |

本机选择 QSV 优先；硬件探测失败、实际编码失败或成品校验失败时回退 CPU。以上为单一样本，测试时旧版正式任务也在运行，不构成所有机器上的统一速度保证。没有用减小分辨率、删除校验或丢帧来制造提速结果。

采用相同范围变换并逐帧对齐，对比解码后的原始图像：CPU 成品 SSIM All 为 0.984807，QSV 为 0.987846。这个客观指标仅证明此样本没有因采用 QSV 出现更大的平均画面误差，不能替代全部录像人工检查。QSV 文件约为 CPU 的 1.62 倍，目标磁盘仍须保留足够空间。

## Computer Use 实操

通过 Windows Computer Use 实际操作验收副本：

1. 选择真实 DAV 样本目录，Channel 01/02 自动对应视角01/02。
2. 点击开始，第一段完成后立即出现于“录像／2026-09-13／视角01”，第二段继续处理。
3. 在转换和完整解码校验期间切换运行、耗时、归档结果表，界面保持可操作。
4. 点击暂停，第一段成品保留。重新打开窗口，点击恢复上次任务并继续。
5. 第一段校验复用约 0.89 秒；修改时间不变、未重新编码。第二段 180 秒录像读取约 0.12 秒、转换 27.50 秒、校验 16.89 秒、归档 0.31 秒，总计约 44.82 秒。
6. 归档结果显示两份成品与各自实际路径；点击“打开归类目录”，Windows 文件管理器进入验收牧场的共享录像目录。
7. 50 ms 界面心跳的 99 百分位间隔约 66 ms；第二轮窗口生命周期最大间隔约 312 ms。未观察到 Windows“未响应”。这不是任意硬盘、任意规模零停顿的承诺。

两份文件来自同一真实录像片段，使用两个通道目录验证映射；属于测试副本，未作为行为训练数据或标注真值。

## 大批量界面和恢复

- 2,000 条任务记录：单次全部刷新实测 127 ms；改为每批最多 150 条，单次约 3.5–8.8 ms，共约 108 ms 的绘制工作，批次间让出事件循环。
- 归档记录只刷新变更行，不反复重绘全部结果。
- 自动回归覆盖每段立即落盘、成品身份与 SHA-256 校验、暂停续跑、落盘后记录写入前中断、变更成品拒绝覆盖、硬件失败回退、旧缓存迁移及预览不得清除未提交成品。
- 完整回归、安装包和发布校验的最终结果保存在交付核对记录中。

## 采用的公开技术依据

- [FFmpeg streamcopy](https://ffmpeg.org/ffmpeg.html)：兼容视频保留原码流，避免不必要的解码再编码。
- [NVIDIA FFmpeg 指南](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.1/ffmpeg-with-nvidia-gpu/index.html)：硬件编码需验证设备与运行能力；本版实测可用后启用，并保留 CPU 回退。
- [FastCopy 官方帮助](https://fastcopy.jp/help/fastcopy_eng.htm)：磁盘 I/O 与计算应分开考虑。原盘顺序处理，目标同盘提交，避免对机械盘无上限并行寻道。
- [Microsoft CopyFile2](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-copyfile2)：文件复制与取消、错误状态有独立语义。本版继续共用常规归类已有的校验复制函数；同盘成品采用不覆盖重命名，不额外全文件复制。
- [腾讯云媒体处理工作流](https://proxy-hk.tencentcloud.com/document/product/1041/48783)、[阿里云媒体处理功能](https://www.alibabacloud.com/help/zh/mps/product-overview/features)：转封装与转码应区分处理。没有把用户录像上传到云服务。

## 保护范围

原始文件和录像机原盘不写入、不删除。临时大文件留在输出盘的“归类缓存”，校验后才进入正式录像目录；只清理本任务已核验的派生媒体。未处理的旧 C 盘缓存按记录渐进迁移，不强行清空。正式任务暂停后保留全部断点，升级后可继续。
