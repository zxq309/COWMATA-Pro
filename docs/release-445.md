# COWMATA Annotator 4.4.5（发布包 COWMATA-Pro-4.4.5）

## 1 协作：数据包全部改为文件夹，直接放到你选的位置（不再压缩）

“派发原始数据包”“生成标注数据包”“接收标注数据包”三步都不再做 ZIP：

| 步骤 | 4.4.5 |
|---|---|
| 标注 → 协作 → **派发原始数据包** | 每个包生成一个 `<牧场>_<类别>_<日期>_标注_<任务>_P00N_原始` 文件夹：`协作清单.json` + 牧场原目录树（所选日期的 JSON 与录像，逐字节复制）。“派发到”给出候选位置——默认 `科牧特_协作标注\原始数据包`、最近用过的位置、各磁盘根目录及其中名字带“派包 / 派发 / 协作 / 转移 / 标注 / 工程 / 共享 / 交换 / 数据包”的文件夹（如 `F:\4090转移派包`），也可输入或“选择其他位置…”；包直接写到所选位置 |
| 文件 → **打开协作数据包** | 选 `…_原始` 文件夹：“放到”默认原位置就地打开；选本机其他位置则先把整个文件夹移过去（同盘改名，跨盘复制核对后删除原处）。旧版 ZIP 仍按原方式解包打开 |
| 标注 → 协作 → **生成标注数据包** | 生成 `…_标注_<修订号>` 文件夹（`协作清单.json` + 标注与证据图），放到“保存到”所选位置，默认与原始数据包放在一起 |
| 标注 → 协作 → **接收标注数据包** | 一次可选多个标注数据包文件夹（旧版 ZIP 也可）。逐个文件按 `协作清单.json` 核对大小与 SHA-256、清单外不许有文件，再按原规则核验并入牧场；之后把文件夹移到“接收后移到”所选位置（默认 `科牧特_协作标注\已接收`，也可“不移动”）。有冲突的整包不并入，移到 `冲突待核对\<任务>` 与核验报告放在一起；被拒收的留在原处 |

可靠性：

- 写包先写进同一位置的隐藏 `.….partial` 文件夹（写入时加锁，每个文件落盘并计算 SHA-256），全部完成、核对清单后才改成正式名字；同名文件夹从不覆盖。中断留下的 `.partial` 下次派包自动清理，别的派包正在写的不会被删。
- 目标位置不能在牧场数据目录里（会被当成牧场资料）；路径会超过 Windows 260 个字符时事先拒绝并写明原因（打开时按标注要写的 `标注工程\…\*.标注.json` 计算）。
- 再次派发并勾选“清理旧派包”：还没人打开的旧派包文件夹删除；已经有人打开或标注的旧文件夹与其派发记录保留，交回的标注照样能接收。

## 2 协作：手动解压 / 复制的原始包、换电脑后接收

| 现象 | 根因 | 4.4.5 |
|---|---|---|
| 标注员把派发的 `…_P002_原始.zip` 用 Windows“全部解压缩”（或 7-Zip）解开，在 `…_原始\扬大_高邮牧场` 里标注；点“生成标注数据包”报“此目录不是已派发任务；请从原始数据包打开工程” | 4.4.4 只认软件“打开协作原始数据包”时写入牧场目录的 `.cowmata-assignment.json`。手动解压时任务清单 `协作清单.json` 在牧场文件夹的上一层，软件找不到，于是整包拒绝 | 原始包文件夹（4.4.5 派发的，或手动解压 / 复制的）都能直接用：选牧场目录、其中的类别目录或数据包文件夹都可以。先核对 `协作清单.json` 与牧场标识、标签范式、每个原始文件的大小，一致才接管为已派发任务；不一致时写明原因（缺文件 / 不同牧场 / 标签范式不同） |
| 派发端换了电脑（`派发记录` 没有带过来）后，接收标注包报“找不到对应的原始派发记录或任务清单不一致” | 接收只认本机 `科牧特_协作标注\派发记录\<任务>.json` | 4.4.5 生成的标注数据包附带完整任务清单（与派发时逐字节相同的摘要）；本机缺派发记录时，用包内清单或 `原始数据包` 里保留的原始包（文件夹或 ZIP）恢复，摘要不符一律拒收；每条标注仍逐个核对本机原始文件的 SHA-256 |

打开工程时若识别到原始包文件夹，同样自动接管，之后的保存、生成标注数据包与软件打开的任务完全一致。

## 3 与 3_训练器 / 4_逆向决策器 / 5_正向决策器 对齐

- 磁盘按流程分五段：`1_下载器` → `2_标注器` → `3_训练器` → `4_逆向决策器`（已知产犊时间，回溯训练与决策全过程、调优）→ `5_正向决策器`（只看待产犊的牛，正向推理，输出风险等级 CSV 与监测报告 HTML 给前端 APP）。
- 下载期间自动启动的实时推理改为 `5_正向决策器\产犊\推理算法\<最新版本>`（仍兼容 4.4.1 的 `4_决策器\产犊\预测算法`）；“下载 → 决策 APP”改名为“风险等级总览”，打开 `5_正向决策器\产犊\前端对接\<版本>\监测总览.html`。
- 决策引擎与训练器同一份代码：动态基线（佩戴初期按数据量收缩）、各提前量独立预警规则与留出评估、`risk_alert` 字段写回 Annotator；训练时额外保存每个提前量的留出预测，供逆向决策器回放。
- 算法包 `lib\` 里的 cowmata_engine / cowmata_tailring 与本版本逐字节相同，`lib\ALIGNMENT.json` 记录每个文件的 SHA-256，`calving.py check` 自动核对。

## 4 其他修正

- 协作窗口：“生成标注数据包”“接收标注数据包”“打开协作数据包”的窗口用完即释放。4.4.4 每用一次都在主窗口里留下一个隐藏窗口和每 0.1 秒运行一次的定时器。
- 决策页（产犊决策）：主提前量概率 `risk_primary`、图里的主提前量曲线与结果表按预警规则逐牛平滑后显示，与阈值线、预警等级、连续预警一致（同 4.4.4）；其他提前量显示原值。`risk` 字段保持逐时刻原值，供决策器按各提前量自己的规则使用。
- 训练：没有“仅台账”样本时跳过学习曲线，样本数不超过实有数量（之前会在交叉验证完成后报错中止）。
- 5_正向决策器（同版本算法包）：实时推理、推理一次、更新模型轮流进行，每次特征提取用独立工作目录；某头牛没算出结果时保留上次结果；`风险等级.csv` 等文件被 Excel 或前端打开时本次跳过、下次补写；`监测记录.csv` 每次佩戴每个决策小时一行，缺的小时自动补齐；更新模型时文件夹被占用会重试，失败则放回原模型；模型暂时不可用时实时推理暂停、恢复后继续，不再退出。
