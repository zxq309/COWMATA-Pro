# COWMATA 3.5.3 视频归类

3.5.2 的问题是仍需整批预览后再复制；3.5.3 改为直接执行，并行识别和真实文件归档交错进行。关闭旧版后启动3.5.3。

## 三步操作

1. 在“数据整理→数据归类”选择“九轴已归类，仅补视频”或“九轴与视频一起整理”，填写牧场、类别、保存方式和可选日期。
2. 点击“批量添加视角01～08目录”，将多个录像目录分别填入对应视角。空白行不添加；同一视角还有其他目录，可继续用“添加录像目录”追加来源并指定同一视角。一起归类九轴时再添加九轴来源。
3. 直接点击“一键执行归类”。不需要先预览或再点一次确认。每条录像识别完成后立即进入复制或移动，核对成功后才显示“已归档”。点击“打开实际目标目录”可查看实际文件。

目录为 `牧场/类别/Video/2026-08-17/视角02/2026-08-17_09-48-09.mp4`。视角01～08保持独立目录，视频不绑定单头牛；已有九轴时按日期匹配全天录像。仅预览按钮明确标注“不复制或移动”，用于可选的只读预览。

## 自动处理规则

- 先按支持的视频后缀过滤，再检查视频内容。非视频后缀不读取、不进入视频列表，保留在来源；九轴及标签按各自规则处理。
- 优先读已支持格式的流内绝对日期时间，只检查开头最多1 MiB，不为命名扫描尾部或建立整段同步。
- 没有流内时钟时读取首帧。海康布局先用轻量的日期与整段数字识别，必要时使用像素识别；首帧读不清则自动尝试开头约1、2、4秒画面，扣除实际媒体偏移回推开始秒。
- 单文件自动尝试设有时间边界，不让个别坏录像拖住整批。仍无法取得可靠日期时间的文件保留并自动跳过，继续其他正常文件，结束时生成异常报告；不弹出逐项确认。
- 默认4路并行，可选1～8。复用未变化文件的OCR与哈希缓存。识别和实际传输交错进行，不等待全部录像识别完再开始写入。
- 复制保留来源；同盘移动后源文件消失、目标文件存在；跨盘仍校验复制并保留来源。同名不同内容追加序号，不覆盖。暂停后已完成项保留，继续任务先恢复已记录项，再处理剩余来源。

## 验证与边界

真实Windows界面分别验证了“已有九轴+三路视频复制”和“九轴+三路视频一起移动”。输入含256 MiB录像、重新封装录像、首帧时间戳被遮挡录像及损坏样本。目标文件在整批结束前已经存在，逐个核对SHA-256；复制来源保留，移动来源消失。非视频后缀没有进入列表；遮挡首帧的样本自动恢复为2026-08-04 23:09:27。

本机两次完整运行约13.3秒、15.9秒，首个文件约9.0秒、6.2秒到达目标。速度取决于磁盘、录像格式、文件大小及缓存，不能据此承诺海量录像固定倍数提速。照片般的开始帧读数和流内开始时间只用于归档命名；后续帧回推属于秒级估计，不表示整段同步已核验。

既有标签的标注内容不改；九轴改名时同步更新标签中的源文件路径。开发实测在隔离副本上进行，没有对用户F盘原始整批目录执行迁移。

## 关闭与更新

关闭数据整理窗口会请求停止后台任务；主界面随后按保存流程退出。无响应的整理工作进程有受控停止边界，已完成文件与恢复记录保留，不通过丢弃标签强行退出。

独立更新进度窗口显示安装、文件校验、启动等阶段及经过时间。校验成功后先启动新版，再清理旧版目录；更新后这一次启动跳过重复联网检查。真实界面启动测试约3.1秒，进度窗口约0.1秒显示，不等同于所有硬件的总安装耗时。旧版更新器的首次迁移不能追溯改变，因此本次建议直接运行3.5.3安装包。
