# COWMATA Annotator 4.3.9（发布包 COWMATA-Pro-4.3.9）

## 1. 本次处理的问题：现场台账“原来的格式上传不了”

| 项目 | 内容 |
|---|---|
| 现象 | 现场台账上传器 1.4.5 导入原格式 Excel，弹窗“尚未上传：设备管理表头不完全匹配，本地修改已保留”，整本台账都无法上传 |
| 影响 | 设备台账（佩戴台账 + 设备管理）无法上传；本软件“端侧数据下载”读到的服务器台账停在上一次 |
| 根因 | 上传器按固定行（第 2 行）、固定列位置逐字比对表头：全角/半角括号、空格或换行、旧列名、换列、表头下移、表外辅助列、多余工作表，任何一项都会拒收整本 |
| 修复版本 | 现场台账上传器 1.4.6（ledger-v1.4.6，经 ledger-latest 签名通道自动升级）；本软件 4.3.9 |

## 2. 修复内容

### 上传器 1.4.6
- 表头契约集中在 `ledger_sheets.py`：
  - `canonical_header`：NFKC 统一全角/半角和括号，去掉空白与不可见字符。
  - `HEADER_ALIASES`：常见旧列名。
  - `REQUIRED`：各表必需列。
  - `locate_layout`：扫描前 12 行，按列名映射字段。
- 导入、原文显示和回写原文件共用同一映射，换过列顺序的表也写回正确的列。
- 表外辅助列的原值保存在“原始单元格”（`__unmapped__`），不参与字段比对；与台账无关的工作表跳过并提示。
- 只有缺少必需列时才停止导入，提示写明缺哪一列和实际表头。
- 样本试验台账表头和 CSV 导入同样统一全角/半角与空白。
- 离线模式（`--offline`）不再弹出重新登录。

### 本软件 4.3.9
- 读取服务器台账 CSV：已知列必须齐全，允许新版上传器新增列；缺列或重复列时提示具体列名。
- 台账备份改为短路径 `csv-backups/<表>-<哈希>.csv`，避免超过 Windows 260 字符限制导致刷新失败。
- `server-upgrade/ledger_sheets.py` 与上传器使用同一份文件。

## 3. 防止同类问题再次出现

1. 复现后再修：新增 13 项回归用例（`test_header_compat.py`），其中 10 项在 1.4.5 上复现同样的拒收。
2. 兼容性回放：本机 34 个真实台账文件在 1.4.5 / 1.4.6 下导入，记录 ID 与字段逐条一致，升级后重新导入不产生重复。
3. 契约同源：服务器端与客户端表头规则为同一文件，测试检查两者逐字节一致。
4. 宽进严出：读取端允许新增列，只对缺少必需列报错，并给出可操作的提示。
5. 发布门禁：安装包在临时目录静默安装，并在安装后的运行库中复跑回归用例；从 1.4.5 升级到 1.4.6 验证数据和授权保留；已安装的 1.4.5 客户端经真实签名通道拿到 1.4.6，校验通过。
