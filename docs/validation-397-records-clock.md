# 3.9.7 按视角记录和录像计时修订

## 任务记录

“查看视频任务记录”打开非模态窗口：总览、视角01至视角20的独立页签。总览分别显示实际处理中、排队、已归档或复用、待核对、累计耗时；每个视角可切换运行记录、耗时明细、归档结果。页签与原任务共用数据模型，不重复加载录像。窗口关闭后停止刷新。

原始录像任务当前仍逐段读取和处理；排队不冒充并行。新窗口只汇总真实的处理中记录，没有改变原盘调度方式。

自动化界面基准：2000 条记录、20 个视角，全部加载约 241 ms，单次视角切换最大 11 ms，状态刷新最大 1.45 ms，10 ms 事件循环心跳的最大间隔约 46 ms。基准使用离屏 Qt 窗口与合成任务记录，不能代替实际桌面操作验收。

## 录像时钟

问题样本的逐帧编号连续、16 位毫秒计数每帧增加 40 ms，但录像机日期发生回拨。原先仅按 FFmpeg 解出的日期时间戳检查，会把这样的录像挡在归档前；PCM 音频时间戳不连续还可能导致 AAC 编码失败。

现在只在逐包核实帧号、计数连续性、音频样本数和音视频偏移后使用连续计时。没有 B 帧、帧序号缺失或计时不均等条件未通过时，不猜测帧率，保留原有严格检查。录像机校时点保存在任务元数据并标记同步待核对。此修复不代表相机日期或传感器同步已经人工确认。

所有修复后的成品完整解码，并核对实际输出帧数。已验证的真实样本：

| 样本 | 输出帧数 | 转换、完整解码与时间轴核对合计 |
| --- | ---: | ---: |
| 音频报错片段，46.28 秒 | 1157 | 12.866 秒 |
| 含日期回拨片段，60 秒 | 1500 | 15.680 秒 |
| 非整帧起点裁剪，约20秒 | 500 | 7.299 秒 |

以上为本机在其他正式任务同时运行时测得，不是所有录像的吞吐保证。兼容 H.264 的自动回归样本仍采用快速封装，75 帧全部保留。原盘和原始文件保持只读。

107 项相关回归通过。完整回归、较长录像和安装包验证的最终日志另存交付核对目录。本修订的 Computer Use 操作被物理 Esc 中止，尚未完成新页签的桌面实操验收；此前版本的 Computer Use 记录不算本次验收。

## 技术依据

- [FFmpeg DHAV 解复用器](https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/dhav.c)：同时读取日期和记录计数，日期变化会影响解出的时间戳。
- [FFmpeg setpts / asetpts](https://ffmpeg.org/ffmpeg-filters.html#setpts_002c-asetpts)：根据已经验证的帧计时、音频样本数设置时间戳。
- [FFmpeg setts](https://ffmpeg.org/ffmpeg-bitstream-filters.html#setts)：兼容 H.264 在保留码流时调整包时间戳。
