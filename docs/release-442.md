# COWMATA Annotator 4.4.2（发布包 COWMATA-Pro-4.4.2）


### 修复：派包加载快、不卡住、出错不中断
- 扫描资料与派发状态：只读目录信息，不再逐个文件解析路径；高邮牧场产犊 615 个设备日由 75 秒以上（未扫完）降到约 1 秒。打开派包窗口自动扫描上次的牧场目录。
- 预览派包方案：只记录文件名、大小与时间戳，不再逐个解析 JSON、不再用 ffprobe 探测录像；3 天约 396 GB 的方案 0.4 秒生成。
- 派发：单个文件出问题不再中断整批——已删除、正在写入（仍在下载/复制）、读取中断的文件跳过并写入派包报告，其余照常打包；一个包失败不影响其他包；4.4.1 中因“录像时长无效”中止的录像（相机按 256 MiB 自动分段的正常文件）现在照常打包。
- 缺少 Temp 或 PPG 的设备日（仍在下载）也可派发，包内注明缺项；没有九轴/PPG 的设备日仍不派发。
- 派包窗口不再独占软件：可最小化，派包期间可继续标注；派包不占用数据目录租约，与下载、数据整理、标注同时进行互不阻塞。
- 进度显示实时速度与剩余时间；视频按原样存入不重新压缩，读取使用顺序读提示，减少对播放的影响。打包速度受同一块存储的读写带宽限制（高邮牧场 USB RAID 实测约 50–75 MB/s）。
- 中断留下的临时包文件在下次派包时自动清理；退出软件或取消时先确认，已完成的包保留。

### 修复：协作派包不再被“下载未完成”卡住
- 4.4.1 在“协作 → 派发原始数据包”时，只要台账核对 / 下载循环不是“完整结束”，或下载器持有 sync.lock，就整体拒绝派包（提示“本轮台账核对与下载尚未完整结束，请先完成下载再派包”）。
- 现在派包只冻结已经落地的文件：下载循环状态仅作为提示写入包内说明，不再拦截；派包与下载、标注可以同时进行，互不占用锁。
- 仍保留的保护：逐文件写入占用检查、文件指纹（大小 / 时间戳 / SHA-256）复核、所选文件被删除时拒绝、传感器 JSON 与设备 / 日期校验。录像缺失或尚未覆盖传感器时段只提示，不阻止派包。
- 派包后新出现的文件 / 视角不会混入已预览的方案，留待下一次派包。

### 修复：标注与视频
- 标签无法确认：草稿确认时重新采集当前画面证据，不再沿用草稿创建时“画面未到位”的旧证据。
- 视频核验：素材索引中区分“录像（可核验）”与“九轴 JSON（信息项）”；按钮按所选行状态启用，并给出针对性的下一步提示。
- 画中画：右下角新增拖动手柄，可自由调整大小，大小随工程保存；原有 小 / 中 / 大 预设保留。
- 暂停后继续播放会回退几秒：精确暂停取得的画面时刻现在同步到共用时间轴，继续播放从暂停位置开始。
- 播放倍速：新增 8× 与 10×（原最高 4×）。

验证：自动化测试 2216 项通过；以高邮牧场 2026-09-06 真实资料（硬链接，含 256 MiB 录像）在下载锁、数据整理租约、录像写入占用同时存在时派包成功，接收端可正常打开。
