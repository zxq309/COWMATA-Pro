# 多人标注与自动回传（3.1.2）

## 分开标注，不要求顺序

先打开包含九轴和录像的工程目录，再用「文件 → 打开九轴」（Ctrl+J）选择任意原始 JSON。也可在素材列表选择、搜索文件名。切换前保存当前成果，只读取选中的九轴及对应录像。

列表区分未开始、进行中、已完成；悬停设备栏可看数量。完成整份检查后点「完成本份」。只有明确确认完成，才会被下次自动跳过。有几条标签不代表整份已检查。

## 标注人员交回什么

1. 完成整份后，用「文件 → 导出 → 完整成果」。结果内嵌原始九轴字节、父记录坐标、同步与录像线索，不包含录像。
2. 将导出的 `.cowmata.json` 和同级「证据」文件夹一起放进约定的回传文件夹。没有保存证据图时不需要空的证据文件夹。
3. 可以放一层人员子文件夹，例如回传文件夹下各有「张三」「李四」；每个人的标签和「证据」保持同级。软件不重排或剪切任何原始数据。

## 负责人只设置一次

「工具 → 多人协作 → 回传设置」选择专用回传文件夹。

- 勾选「自动发现回传成果，并提醒核对接收」：程序约每 10 秒轻量核对一次。两次状态一致、且文件没有写入占用后才尝试接收。默认先弹窗询问是否核对接收。
- 需要自动化时，再勾选「自动接收核验通过、无冲突且明确已完成的整份成果」。播放、读取、导出或记录动作期间延后接收；不会突然打断视频。
- 自动核对的是文件完整性、九轴身份、原始范围和证据图片校验值，不是自动判定行为标签的科学正确性。
- 可随时用「接收成果」手动多选；暂缺源文件或证据补齐后，用回传设置中的「重新核验待处理成果」重试。

无需逐份选择输出位置。接收后的活动标注进入既有 `标注工程/annotations`；可回看的回传原件在 `标注工程/回传`，证据图片按内容去重。`project.json` 记录完成进度，接收报告保存在回传目录。数据工程只有原来的一个管理目录。

## 不能自动吞掉的情况

| 情况 | 行为 |
| --- | --- |
| 同一份内容、同一份成果再次交回 | 判重，不重复覆盖 |
| 本地和回传对同一九轴有不同人工结果 | 双方保留，回传版归档，活动成果不覆盖；用历史回看比较 |
| 文件名相同但原始九轴 SHA-256 不同 | 拒绝按名字匹配 |
| 改名后的原始九轴尚未在本工程建立身份 | 先打开这份原始 JSON，再重新接收；不为了找它读取所有录像 |
| 回传的是片段而不是整份，或仅标为进行中 | 不自动标记整份完成；进行中整份可以手动接收，片段用历史回看 |
| 缺少图片、文件损坏、源文件缺失或正在复制 | 保留待核对，不接收为完成 |

历史同步关系随回传原件保留，但不会自动覆盖负责人当前工程的全局相机校准。多人不能同时写同一个工程：现有单写锁仍生效；各自使用独立副本，最后接收成果。
