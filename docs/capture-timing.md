# 新旧 JSON 与录像对齐（2026-09-07）

设备开发人员已确认：create_time 是设备开始采集的时间；update_time 是服务器收到数据的时间。V2 帧内 uint32 毫秒计数每次采集重新计时，其零点对应 create_time。

| 记录 | 读取方式 | 时间质量 |
| --- | --- | --- |
| V2，22 字节/帧 | 4 字节毫秒计数 + 9 个 int16；支持计数回绕 | 设备采集时钟 |
| V1，20 字节/帧 | 2 字节间隔 + 9 个 int16 | 保留相对时间，首帧起点为估计 |
| V0，18 字节/帧 | 9 个 int16，20 ms 间隔 | 保留旧兼容，时间为估计 |

用户这次提供的 11 份文件（旧一小时、新一小时、半小时三组）实际都是 V2；不按文件夹名决定协议，也不把半小时拉伸成一小时。

V2 每个样本的绝对采集时间 = create_time + 首帧计数 + 现有九轴相对位置。相对时间仍从第一帧为 0，避免改动已有标签。导出片段保留原帧字节、原记录坐标与采集时间线索，回看不重复累加截取偏移。服务器接收延迟不改变采样间隔或录像定位。

工程使用显式时区偏移（默认中国 UTC+8），而非依赖客户电脑时区。录像索引仍使用画面中的相机日历时钟：设备与相机可能有偏差，所以自动定位是候选浏览，不等于已经人工校准。

- 新打开、尚无校准的记录：自动联动录像，无须先猜文件名或找文件。
- 已有人工校准：完整保留，不被设备起点覆盖；第一次人工钉点会替换自动起点，不把自动起点算作第二个人工点。
- 真值确认和跨九轴续接：仍要求已核对的牛号、设备、人工校准及有效录像；没有校准时提示核对，不硬拼。
- 历史工程首次打开仅重建过期九轴元数据；视频 OCR、素材 SHA-256 身份和已有人工成果不删除。
- 文件间有实际时间缺口就保留。无录像且尚未核对时钟时，不能因此把后续九轴全标为正常/负样本。

更早的验收文档曾将 create_time 当作语义未知或服务器时间，那是当时的信息边界；时间含义从本版起以此说明为准，历史人工标签不自动迁移。
