# 原生录像时间与快速定位（3.1.2）

## 时间来源的优先级

1. 九轴使用设备采集时间（`create_time`，以及新版样本内部计数/时间戳）；`update_time` 是服务器收到数据的时间，不用来对齐。
2. 已保存的人工时钟校准优先保留。按当前九轴实际起止查询，多留前后各 30 秒供浏览；包含跨越 JSON 起点和终点的完整小录像，不按文件名大小推断时间。
3. 对本次样本支持的 MPEG-PS 私有录制时间先做小范围首尾预读；只为命中的候选读取完整数据包头和 SHA-256，不解码整个录像。编号重置、同名或乱序不能替代时间和内容身份。
4. 原生时间候选先供粗定位与播放，后台进行独立画面抽查。一致后才标为已核验；有冲突、缺口或不支持的格式，继续 OCR / 人工复核。尚未检索不等于没有录像。

## 已验证的适用范围

用户提供的四个 256 MiB 文件虽扩展名是 MP4，实际容器为 MPEG-PS：两份包含 HK1 描述符，两份包含神眸 PES2 毫秒时间。实现严格验证包边界、日历、时间连续性及文件状态；不从任意压缩画面字节搜索“看起来像时间”的数字。

HK1 日期按设备墙钟读取；PES2 epoch 按工程时区转换，默认 UTC+08:00，不偷偷沿用电脑本地时区。该布局是样本验证结果，不宣称所有品牌/固件通用。不使用 Windows 创建/修改时间当录像起点，也不直接相信异常的容器总时长。

全包时间检查会拒绝倒退、异常跳变或过长未解析区域。图像 OCR 不直接套用原生时间来“补正确数字”。最多进行五个独立位置的有时限抽查；不能确认时仍保留待复核，不伪造可靠证据。

## 播放与存储

这些内存卡录像可能预分配空间，尾部存在无效/孤立内容。按关键帧字节范围抽取短窗口，在内存中建立连续播放传输；不修改原始文件、不重编码、不产生一整套同体积代理视频。播放过程中保留实际时间，不把数秒关键帧预读压缩成瞬间。

新工程默认「单路优先」：先准备主视角，辅路逐个读取静止图。画面内点击播放会切换唯一播放视角；未播放画面标明暂停及截图时刻，不参与当前真值确认。全局暂停时各路依次读取同一标注时刻的原片精确帧。「流畅优先」周期刷新辅路预览，「多路全速」同时解码各路，均可手动选择；全速等待过久会降级提示。原项目保留已保存的偏好。

原生播放器调用位于独立解码线程，操作只投递最新意图，不积压过时跳转。每路 CPU 解码线程数受限，GPU 硬件解码仍自动尝试。真实画面到位受关键帧、磁盘和驱动影响，不等于按钮响应延迟；不保证任意电脑八路全速或所有操作硬性低于 25 ms。见 [播放与实测](playback-performance-312.md)。

## 操作入口

- 文件：打开工程、打开任意九轴、保存、历史回看、导出。
- 编辑：完成本份、下一份、撤销/重做、标注与证据。
- 视图：素材/标注列表、布局和播放设置。
- 工具：多人协作、录像索引、时间同步、候选预测。
- 帮助 → 关于：软件与公司信息、版本号、检查更新。

常用命令留在主界面，次要命令分类收起；详细解释放到悬停提示。参考 [Microsoft 菜单设计](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/menus-and-context-menus)。
