# 卧倒过程（LYING_DOWN）尾环标准算法 liedown-tailring-1

日期：2026-09-25。数据：`F:\科牧特_数据集\COWMATA_Behavior_Dataset`，只读使用，原始与标签字节未改动。

## 1. 数据中找到的规律

口径：243 份带事件标签的记录（240 h），124 次卧倒（去重后），来自 23 头牛。设备为尾环九轴，50 Hz。

| 规律 | 实测 | 物理解释 |
|---|---|---|
| Y 轴始终沿尾，承担大部分重力 | g_y ≈ −0.9 g（站、卧都是） | 尾根下垂 |
| 站立：Z 轴朝上，基本无横滚 | g_z ≈ +0.37，横滚 ≈ 17° | 尾巴垂在坐骨后方 |
| 躺卧：尾巴向一侧翻 | g_z ≈ 0，横滚 ≈ 94° | 后躯落地，尾巴贴向左或右（X 的符号区分左卧/右卧） |
| 卧倒时姿态方向改变 ≥10° | 99.2%（中位 43°） | 站姿到卧姿的永久转移 |
| 卧倒时 Z 分量下降 | 96.7%（中位 −0.50 g） | 与起立方向相反（起立时 98% 上升） |
| 过程中有陀螺仪爆发 ≥18 dps | 96.7%（中位 28 dps） | 腕关节跪地、后躯下落 |
| 新姿态在其后 30–90 s 保持 | 转移后偏离中位 3.8° | 卧回合通常持续数十分钟 |
| 过程时长 | 中位 6.6 s，P5–P95 3.0–25 s | — |
| 同时满足上述四条 | 91.0% | 这就是"卧倒规律" |

另外发现一个硬件问题：设备 546C50CA01F1 静止时加速度模长约 1.95 g，Z 轴有约 +1.95 g 的零偏；546C50CA090B 静止模长约 0.84 g。算法先在每条记录里自动检测并校正零偏（1 g 球面拟合），否则这类设备上的姿态特征会失真。

## 2. 算法结构

参照 Achour 2019 的"状态 + 转换 + 状态机"，以及 Ledgerwood 2010、Kok 2015 的姿态回合规则：

1. **加速度零偏自校准**：取静止样本，模长偏离 1 g 超过 0.07 时拟合常量偏置。
2. **10 Hz 分析网格**：计算重力方向（1 s 均值）、陀螺能量和抖动纹理；采样缺口保持 NaN，不跨缺口插值。
3. **候选点**：前 12 s 与后 12 s 重力方向夹角的峰值，要求 ≥8°、间隔 ≥8 s。候选覆盖率 98.4%。
4. **49 个物理特征**：短/长窗姿态变化、ΔZ、横滚、爆发比、静止比例、新姿态保持度等。
5. **姿态层**：逐秒站/卧随机森林。逐牛留一时逐秒准确率 92.6%。由它给出每个候选"之前/之后是卧姿"的概率，共 6 项上下文特征。
6. **事件层**：数值随机森林（200 棵树，不使用 pickle），输出分数后按 20 s 做非极大值抑制。
7. **边界**：由姿态转移进度的 5%–95% 确定，再减去 LOCO 学到的系统偏差（起点 +0.73 s，终点 −2.51 s）。
8. **兜底**：没有模型文件时用四条物理规律打分（`law_score`）。

代码位置：

- 算法：`cowmata_tailring/algorithms/liedown.py`
- 训练与再调参：`scripts/train_liedown.py`
- 测试：`tests/test_liedown_tailring.py`
- 程序接入：`algorithms/evidence.py` 按 `algorithm == "liedown-tailring-1"` 分派到原始 50 Hz 信号。这样候选标注、识别、产犊证据/躺卧占比都能直接使用新算法。

## 3. 实测验证

验证按牛留一（LOCO），38 头牛各做一折。阈值与边界偏差在同一 LOCO 结果上选取，这一点可能略微偏乐观。

| 阈值 | 召回 | 相对标签的精确率 | F1 | 未匹配/小时 |
|---:|---:|---:|---:|---:|
| 0.20（默认） | 95.2%（118/124） | 77.6% | 0.855 | 0.14 |
| 0.40 | 87.1% | 82.4% | 0.847 | 0.10 |
| 0.50 | 80.6% | 82.6% | 0.816 | 0.09 |

补正边界偏差后，起点误差绝对值的中位数为 2.1 s，终点为 1.2 s。

**关于"未匹配"的检出**：34 个未匹配检出我已逐个看过九轴波形。约 23–25 个符合"站立活动 → 爆发 → 安静卧姿 + Z 下降"的完整形态，很可能是真卧倒但数据集中没有标注；分数 ≥0.5 的 21 个全部是这种形态。其余大多是卧着时的姿势调整。据此估算，实际精确率约 0.93。这个结论只来自九轴信号，仍需视频确认，清单见 `疑似漏标卧倒-待视频复核.csv`。

**与现行 v1 的对比**：同样 243 份记录，走程序内的同一推理入口，按同一匹配规则计算：

| 版本 | 召回 | 精确率 | 候选/小时 | 未匹配/小时 |
|---|---:|---:|---:|---:|
| v1 cowmata-395-motion-1279A（这些记录基本都是它的训练数据） | 82.3% | 10.6% | 4.00 | 3.58 |
| 本算法（LOCO，新牛视角） | 95.2% | 77.6% | 0.63 | 0.14 |

**野外合理性**：抽取 400 份无标注记录（388 h）运行最终模型，得到 9.47 次/天。文献值为 9±3 次/天（Ito 2009），两者吻合，说明没有系统性过检。

推理耗时约 0.26 s / 1 小时记录。

## 4. 数据增加后如何再调参

在源码根目录用 Python 3.12+ 运行：

```powershell
python scripts\train_liedown.py --dataset "F:\科牧特_数据集\COWMATA_Behavior_Dataset" `
    --output "F:\科牧特_模型\行为识别\runs\liedown-YYYYMMDD-01" --workers 16
```

- **16 路并行解码**：按原始文件 SHA-256 缓存，只处理新增记录。
- **每次运行都会重新完成以下步骤**：统计规律（`卧倒逐事件规律.csv`、`评估报告.json → law`）、姿态层与事件层 LOCO、阈值选择、边界偏差、逐牛评估、漏检清单、疑似漏标清单、无标注合理性检查。
- **产出是标准 suite 目录**（`suite.json` + `lying_down.json`），在"行为识别 → 训练与识别"中手动导入即可。旧版本可随时回退。
- **建议的闭环**：视频确认疑似漏标后补标，再重跑。补标会同时提高召回、提高精确率，并让边界偏差更准。

## 5. 限制

- 当前只有 23 头有卧倒标签的牛，且集中在少数设备上。新牛场、新佩戴方式要先跑 LOCO 报告再上线。
- 候选点要求姿态变化 ≥8°。极少数姿态变化很小的卧倒（本数据 2/124）不会进入候选。
- 分数不是概率；输出仍是待人工复核的候选区间。
