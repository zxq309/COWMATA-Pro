# COWMATA Pro 3.8.2：算法迭代与产犊证据

## 从哪个版本接续

本版接续 3.8 的 feature/algorithm-workbench-38 开发分支，合入 3.8.1 的更新兼容、完整数据集增量更新和归类页签修复。
旧分支中已有训练核心和首轮模型，但版本管理、候选适配和产犊证据界面尚未完成；本版补齐这些入口。

## 使用入口

1. **标注与复核 → 算法管理**：选择现有 COWMATA_Behavior_Dataset，分析共同规律或训练新版本。新版本完成后查看评价表，点击“使用所选版本 / 回退”。
2. **候选标注**：默认使用当前算法版本的起立、卧倒、努责三个模型；已有旧版模型仍可选择。预测区间保留为待复核候选，人工看录像、选择边界后才能建立草稿。
3. **健康与繁殖 → 产犊**：计算当前九轴，或选择 COWMATA_CalvingPred_Dataset 更新整套证据。按牛查看四项趋势、证据明细及监测评价，可另存 CSV。

## 算法独立更新

代码集中在 cowmata_tailring/algorithms/：

| 文件 | 职责 |
|---|---|
| dataset.py | Raw/Label 索引、重复原始记录合并、牛号冲突处理 |
| features.py、analysis.py | 一秒特征、信号缺口处理、缓存和共同规律报告 |
| training.py、metrics.py | 三类共享模型、嵌套阈值选择、留出评估 |
| registry.py | 模型哈希校验、独立版本安装、切换与回退 |
| adapter.py、runner.py、worker.py | 候选接口、受限资源后台进程、取消 |
| posture.py、evidence.py | 躺卧推断、四项证据与历史基线 |
| workbench_ui.py | 算法管理和产犊证据窗口 |

默认工作目录是当前用户 LOCALAPPDATA/COWMATA/algorithms。原始数据继续留在现有数据集目录。
模型版本保存在 versions；运行清单、标签快照和评价报告保存在 runs；特征缓存保存在 cache。
更新应用不会覆盖这些算法成果。发布包中的初始模型位于 assets/algorithms/events-20260915-01。
部署模型只包含三个数值模型及汇总报告，不包含原始记录、逐牛标签或训练路径。
模型不是可执行 pickle。

## 固定的数据规则

- 通用行为合并牛号训练与展示，同一原始记录及其副本不能跨训练和验证。
- 努责和产犊关键事件保留牛号、时间关联；努责按牛隔离验证。发情相关爬跨保留个体关联。
- 同源牛号冲突记录只能在明确启用通用事件池时提供通用事件，不能参与个体产犊计算。
- 未完整审核的未标时段不是确定负样本。当前训练使用降低权重的未标背景，并在模型中保存这一限制。
- 数据增加或标签修改后，由现有目录重新建立索引；原始信号特征未变化时可复用缓存。无需复制一整套时间戳数据集。
- 独立后台进程最多使用两个逻辑 CPU，数值库单线程；取消或关闭窗口会停止其拥有的进程。

## 躺卧占比如何计算

卧倒结束后推断为躺卧，起立结束后推断为站立。动作过程单列。
记录开始、采样缺口之后、重叠冲突区间保持未知；连续同方向动作之间的矛盾区间不能自动补成确定姿态。
同一记录内跨10分钟显示窗口继续传递状态，最多保持一小时；不同原始记录暂不自动连接，避免跨牛或跨缺口误接。

表中同时显示：

- 已知姿态中的躺卧占比：躺卧时间 /（躺卧时间 + 站立时间）。
- 姿态覆盖率：已知姿态时间 / 有效观测时间。
- 全窗口占比下界与上界：分别按未知及缺失时间不躺卧、全部躺卧计算；过渡动作单列。

这些是转移动作推断的证据，不是直接姿态测量。覆盖率不足时，不应把局部占比当作整段占比。

## 四项证据与输出边界

每个原始记录独立生成10分钟窗口，按牛显示：

- 活动量：加速度动态变化的相对指数，附有效九轴覆盖率，不称为步数。
- 躺卧：上述推断占比、覆盖率、未知和缺失时间。
- 努责：候选起始次数和候选区间并集时长，不称为人工确认次数。
- 温度：原始传感器温度中位数、样本数；缺失保持空值，不替代直肠核心体温。

活动和温度变化量与同牛此前24小时的可用窗口中位数比较，至少需要6个历史窗口。
当前实现只展示证据，不输出低中高风险、未来若干小时产犊概率或预警提前量。
监测评价表展示证据覆盖情况；预警准确率、灵敏度和提前量需要未来经过验证的决策模型与连续审核真值，当前不计算。

## 更新安装

本版保留 3.8.1 的离线升级桥接。遇到旧仓库地址校验错误的 3.6.x 客户端，先运行一次新版安装包，之后才能走新版自动更新流程。
源码 ZIP、便携 ZIP 和安装 EXE 为三个发布附件；程序发布和模型切换互相独立。
