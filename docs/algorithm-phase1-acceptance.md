# 第一阶段算法预览验收 · 3.1.0a1

日期：2026-09-06。此版本是分阶段预览，不是“所有功能、所有硬件都零问题”的最终交付。
保留原 3.0.0 便携包不覆盖；本阶段未重命名、重切或改写用户原录像/九轴。

## 已实现

| 要求 | 实现与保护 |
|---|---|
| RapidOCR＋PP-OCRv6_medium | 已下载官方 det/rec 权重，固定 RapidOCR 3.9.2；运行时校验 SHA-256，只加载本地模型；缺失/损坏不会偷偷回退旧模型或联网 |
| 四角时间戳 | 保留四角候选、预处理多次一致性、完整日期合法性、按相机 ROI 提示、邻帧重试和时间推进核查 |
| 自动接下一份九轴 | 仅同设备＋同牛号＋下一份至少两个有效校准点覆盖当前时刻＋唯一匹配；不使用 create_time 推断连续采集 |
| 播放不被续接打断 | 校准检索及九轴读取放后台；交付到界面时再次核验时刻、牛号和源文件；不重置视频位置/视角/倍率 |
| 未校准则提醒 | 下一份未校准、牛号不明、数据缺口或候选重叠时，不强行加载；保持视频可浏览，持续提示核对 |
| 全工程覆盖提醒 | 区分当前视角无画面、其他视角有画面、中间缺口、全部录像范围结束、索引未完成、时间待核验、同步未知 |
| 杂文件 | 图片、说明、索引侧文件、下载临时后缀、压缩包不作为录像任务；非九轴 JSON（含普通数组）标记 ignored，不反复解析 |
| 损坏素材 | 真正损坏的九轴/录像保留 invalid 异常，不能以“忽略杂文件”为由掩盖数据问题 |
| 便携性 | 私有 Python/Qt/VLC/FFmpeg/ONNX 和模型均随包，不安装/替换系统环境，不要求删除旧 .venv |

旧 OCR 索引继续复用。升级不会导致海量文件全部重跑，需要时对所选录像执行“重新建立所选视频索引”。
自动续接不改变各文件原始样本时间；跨文件动作仍记录各自源片段和共同事件组。
没有视频证据不等于“正常”，不会自动给后续九轴贴阴性标签或丢弃原始数据。

五份原片的首部、尾部与约每 5 分钟抽样完整跑完：40 个采样目标中最终 39 个有完整时间读数，1 个待人工核验。
这不是独立人工标定的“97.5% 准确率”；它只是本轮完整读数可用率。邻帧替代和时间一致性检查证据均在报告内。

真实 libVLC 播放验证使用隔离的合成测试工程，非真实牛行为标注：

- 双路 1 倍、2 倍：每路自动跨小视频；九轴由第 1 份续接到第 2 份；第 3 份未校准，保留第 2 份并持续提示；视频不回退、不因九轴加载暂停。
- 八路 1 倍、2 倍：恢复全部八路配置，所有视角跨到下一文件，九轴按同一保守规则续接，未校准第三份未加载。
- 另测后台查找可取消，关闭联动或过期的异步结果不能强制改变当前记录；自动换记录时不重置视角、倍率和播放位置。
- 使用软件自带解释器，将 PATH 限制到系统基础目录、禁止 Python 网络连接，成功构造工作台、加载 v6、读原片首帧并解析 179366 个真实九轴样本。原视频与 JSON 校验未变。

实测发现并修复的界面联动缺陷：

1. 未校准提示曾被下一次播放刷新覆盖，现持续显示。
2. 首次载入九轴时保存了尚未恢复的空播放器配置，导致八路恢复成两路；现不再过早保存空状态。
3. 初始参考时间触发的 dirty 标记曾阻止首次九轴读取，直到下次约 20 秒目录扫描才加载。现仅在确有旧记录需要保存时执行保存失败门控。相同八路受控工程就绪从约 22.3 秒降为约 1.42 秒，原有标注保存失败的保护仍通过回归。

## 尚未达到最终验收的部分

- **八路最终性能仍需更多验证**：已修复首次九轴约 20 秒的错误等待，同一受控工程约 1.42 秒就绪；跨片期间部分视角仍有短暂加载，VLC 出现过解码/时间参考告警。功能断言通过不等于任何硬件都不卡顿。此预览包不承诺八路原画丝滑。
- 本机使用 RTX 2080 Ti；受控多视角片段为 640×360。此前高清负载测试和本次受控续接测试不能替代多个物理相机的完整实战验收。
- create_time 语义不能从单份 JSON 确证。本版不依赖它完成精确同步；两点人工对应、独立相机时钟校准和不确定区间仍必须保留。
- OCR 五分钟抽检能发现部分跳变，不能证明两次抽检之间绝对没有短暂跳变；异常事件附近应追加人工对应/校准点。
- 现代化界面尚未替换。已确认 A 观察优先为默认，B 多视角网格、C 波形画中画保留，标签轨道独立；详见 ui-next-stage-proposal.md。
- 海量完整工程、更多监控型号、长时间连续运行和不同硬件仍需后续实测。最终交付前先解决可复现的性能问题，再验收新版界面与便携包。
