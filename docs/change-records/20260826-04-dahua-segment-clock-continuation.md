# 乐橙相邻视频分段时钟续接

## 问题现象

切换到相邻视频时，原实现把当前九轴播放头直接当作新视频的 0 秒位置。只有用户恰好停在上一段的精确末尾时该假设才成立；提前切换、末帧误差或重复跨段都会让后续视频的绝对时间逐段漂移，并需要重新钉住。

## 根本原因

`DualAnchorPrecisionV2Mixin.open_video()` 没有使用乐橙相邻录像保留的分段时间关系，而是无条件执行：

```text
新视频起点 = 九轴数据创建时间 + 切换前播放头
```

这会丢失第一次人工钉住得到的稳定视频基准。

## 修改方案

1. 只对同目录、文件名前缀和扩展名相同、编号严格相邻的两个文件尝试分段时钟续接。
2. 两个文件都必须通过乐橙/Dahua MPEG-PS 文件头识别。
3. mtime 方向必须与文件编号方向一致，时间差必须在 1 分钟至 6 小时内。
4. mtime 差还必须与两个起点之间较早片段的真实扫描时长接近，容差与时长仲裁一致，为 5 秒或时长的 8%（取较大值）。向后切换时若新打开的较早片段还没有可用时长，则不启用分段时钟。该条件拒绝几秒复制时间和明显录像中断。
5. 条件全部满足且时间轴已钉住时，新片段起点等于“旧片段已钉住起点 + mtime 差”，九轴播放头定位到新片段的真实起点。
6. 任一条件不满足时保留原有 `continuation` 行为，不阻止用户切换视频。

## 修改文件

- `cowmata_tailring/media/dahua_segment_clock.py`：相邻编号、格式、mtime 方向和时长一致性校验。
- `cowmata_tailring/media/mixins/dual_anchor_precision.py`：在视频源切换时应用可信分段时钟并更新播放头。
- `cowmata_tailring/media/mixins/playback.py`：显示“乐橙分段时钟”对齐方式。
- `cowmata_tailring/ui/translations.py`：补充分段切换状态翻译。
- `tests/test_dahua_segment_clock.py`：覆盖前进、后退和各类回退条件。
- `CHANGELOG.md`：记录用户可见变化。

## 数据和兼容性影响

- 不修改、不删除、不移动视频或标注数据。
- 第一次人工钉住仍是绝对基准；本功能只在相邻乐橙文件间传递该基准。
- 普通 MP4、右1、海康、非相邻文件、复制时间异常和长录像间断继续使用原逻辑。
- `segment_clock` 会作为对齐方法保存在工程中；旧版本即使不认识该显示名称，也仍能读取已保存的 `videoStartWall` 数值。

## 已知风险

mtime 不是容器内的强制录像元数据，因此本功能不会无条件信任它。若文件被复制后仍恰好形成与真实时长接近的相邻 mtime 差，校验可能无法识别；此时可重新钉住或回滚本提交。非相邻跳转不会推算跨越多个文件的累计时钟。
