# 全零视频占位文件识别

## 问题现象

右1和海康目录包含固定 256 MiB 的全零占位文件。它们与正常 `.mp4` 文件同名同尺寸，原工具会交给 VLC 打开，用户看到黑屏、0 时长并等待播放结束，只能逐个试错。

## 根本原因

视频打开和前后导航只按扩展名枚举文件，没有在 VLC 之前检查空文件或全零占位特征。

## 修改方案

1. 根据绝对路径、文件大小和纳秒级 mtime 缓存检查结果。
2. 正常文件先读取开头 4 KiB；检测到非零数据立即返回，不继续读取。
3. 开头为零时再抽样文件中部和尾部各 4 KiB。三个位置均为零时标记为疑似全零占位。
4. 用户直接打开占位文件时，在 VLC 之前阻止并显示文件名和原因，保留当前已打开的视频。
5. 上一个/下一个视频导航按需跳过连续占位文件，并显示跳过数量。

该检查不会顺序读取完整 256 MiB 文件，因此不会产生明显等待或额外磁盘占用。

## 修改文件

- `cowmata_tailring/media/video_file_health.py`：轻量占位检测、身份缓存和可播放邻居查找。
- `cowmata_tailring/app/mixins/release_hardening.py`：打开前阻止空占位文件。
- `cowmata_tailring/ui/main_window.py`：前后导航自动跳过占位文件。
- `cowmata_tailring/ui/translations.py`：补充状态和错误提示翻译。
- `tests/test_video_file_health.py`：覆盖识别、缓存失效、误判保护、导航和打开拦截。
- `CHANGELOG.md`：记录用户可见变化。

## 数据和兼容性影响

- 不修改、不删除、不移动任何视频文件。
- 占位文件仍保留在磁盘，只是不再交给 VLC。
- 检查缓存仅存在于当前进程内，文件大小或 mtime 改变后自动重新判断。
- 三点抽样结果称为“疑似全零占位”，避免声称已经完整读取文件。

## 验证方法

- 用空文件、全零文件和正常 MPEG-PS 文件验证分类。
- 用“头尾为零、中部非零”的文件验证不会误判。
- 修改文件身份后验证旧缓存不再生效。
- 验证多个连续占位文件会被前后导航跳过。
- 对 `J:\` 中右1和海康的已知占位及正常文件做只读检查和耗时统计。
- 运行完整测试、Ruff 和 Git 差异检查。

## 已知风险

三点抽样不是全文件证明。如果某个特殊有效文件的开头、中部和尾部抽样区域恰好全部为零，它会被标为疑似占位；用户仍可回滚本提交或使用外部播放器检查该文件。当前目标目录的正常 MPEG-PS 文件均在开头立即包含非零包头，不符合该误判条件。
