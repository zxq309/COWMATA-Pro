# 视频首帧就绪后再暂停

## 问题现象

部分视频打开后不会立即显示画面，播放器区域保持黑屏。此时点击播放，按钮仍显示“初始化后播放”，通常要继续播放数秒后画面才出现。

这个问题在时间轴缓存已经存在时反而更容易出现：时长很快显示正确，但 VLC 解码器和视频输出窗口还没有完成初始化。

## 根本原因

播放器打开文件时会短暂播放，以便 VLC 建立解码器并输出首帧。修改前的自动暂停只等待“时长已经可用”，随后固定延迟 `80ms` 就暂停：

```text
打开视频
  -> 时间轴缓存立即提供可信时长
  -> 等待 80ms
  -> VLC 尚未创建视频输出就被暂停
  -> 没有首帧，画面保持黑屏
```

VLC 配置的文件缓存为 `1000ms`。暖缓存情况下，可信时长可能早于 VLC 的视频输出和首帧到达，因此 `80ms` 不是可靠的解码就绪条件。

同时，旧逻辑把“收到播放后又收到暂停事件”作为初始化完成信号。如果 VLC 在第一次状态轮询前已经被暂停，程序从未观察到播放状态，初始化状态就可能一直无法完成。点击播放只能排队为“初始化后播放”，不能直接恢复解码。

## 修改方案

1. 媒体引擎增加 `libvlc_media_player_has_vout` 查询，用于确认 VLC 已创建视频输出。
2. 初始化状态分别记录可信时长、播放状态、首帧条件和暂停请求，不再用单一播放状态推断所有条件。
3. 只有同时满足以下条件才发送自动暂停：
   - VLC 已进入播放状态；
   - 视频输出数量大于 `0`；
   - 当前媒体时间已经从 `0ms` 向前推进。
4. 只有可信时长已产生且上述首帧暂停已经确认，才解除初始化状态并恢复到目标位置。
5. 初始化未完成时点击播放，可主动重新调用 VLC 播放，避免按钮只能排队而不能唤醒解码器。
6. 打开后 `3s` 仍无首帧时自动重试一次播放；`7s` 仍失败时停止等待并解除界面冻结，显示可操作的错误提示。
7. 每次打开使用递增代次隔离定时回调，旧视频的重试或超时回调不能作用于后来打开的视频。
8. 打开失败和窗口关闭时同步恢复或清理全部新增状态。

修改后的事件顺序：

```text
打开视频
  -> VLC 开始解码；时间轴扫描并行进行
  -> VLC 创建视频输出且媒体时间推进
  -> 自动暂停首帧
  -> 可信时长就绪
  -> 恢复目标位置并解除界面冻结
```

首帧可能先于时长到达，也可能晚于时长到达；两个顺序现在都能正确完成。

## 性能与磁盘影响

- 不生成视频副本、MKV 或新的大文件。
- 不增加 FFmpeg/FFprobe 扫描次数，也不改变现有轻量时间轴缓存格式。
- 首帧解码与时长扫描并行，不会等待时长扫描结束后再启动解码。
- 暂停会等待真正可显示的首帧，而不是固定等待 `80ms`。这段时间是消除黑屏所必需的 VLC 解码时间。
- `3s` 重试只在首帧没有出现时触发，正常打开不会执行第二次播放。
- `7s` 超时用于避免损坏文件、解码器异常或显卡输出异常导致界面永久冻结。

## 修改文件

- `cowmata_tailring/media/engine.py`：绑定 VLC 视频输出查询并暴露输出数量。
- `cowmata_tailring/media/mixins/playback.py`：把加载后自动暂停改为可覆盖的调度入口。
- `cowmata_tailring/media/mixins/priming_playback.py`：实现首帧就绪状态机、重试、超时和代次隔离。
- `cowmata_tailring/app/mixins/cancel_safe_open.py`：打开失败时恢复全部初始化状态。
- `cowmata_tailring/app/mixins/timer_shutdown.py`：关闭时使定时回调失效并清理初始化状态。
- `cowmata_tailring/ui/translations.py`：增加重试和超时提示的英文翻译。
- `tests/test_priming_position_restore.py`：覆盖暖缓存、冷缓存、VLC 视频输出、重试、超时和失败恢复。

## 已知限制

- `libvlc_media_player_has_vout` 能确认视频输出已创建，媒体时间推进能确认解码已运行；自动测试不能直接判断显示器上的像素内容。
- 如果 VLC 无法解码文件、视频输出模块异常或显卡驱动失败，程序会在 `7s` 后解除冻结并提示重试，不会把无法产生的画面伪装成初始化成功。
- 本次修改解决初始化过早暂停导致的黑屏，不改变源视频本身的编码、关键帧间隔或损坏情况。
