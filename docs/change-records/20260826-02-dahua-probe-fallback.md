# 乐橙 ffprobe 失败后备

## 问题现象

乐橙时长探测原先完全依赖 ffprobe。ffprobe 未安装、路径失效、启动失败、超时或返回错误时，播放器只能退回不可信的 VLC 原始时长，可能把约 33 分钟录像显示为 11 分钟、几秒或 0。

## 根本原因

已有的 MPEG-PS 字节扫描器能够识别帧、关键帧和 PES 时间戳，但只在 ffprobe 成功之后运行。ffprobe 失败会提前终止整个乐橙探测流程。

## 修改前行为

```text
缓存未命中 → 查找/运行 ffprobe → 失败 → VLC 原始时长
```

## 修改方案

新的探测顺序：

```text
有效缓存
  → ffprobe 包扫描 + 内置 MPEG-PS 字节扫描
  → ffprobe 不可用时仅运行内置 MPEG-PS 字节扫描
  → 内置扫描也无法确定帧数或帧率时才退回 VLC
```

内置扫描直接解码视频 PES 的 90 kHz 时间戳，并按相邻时间戳对应的帧序计算平均帧间隔。它会过滤回退、异常大跳变以及 5 ms 至 250 ms 范围外的单帧间隔。由此可以在不依赖通用 PTS 总跨度的情况下计算时长，并继续生成关键帧和时间戳索引。

## 修改文件

- `cowmata_tailring/media/dahua_duration.py`：增加 PES 时间戳解码、帧间隔推导和内置后备探测。
- `cowmata_tailring/media/safe_engine.py`：ffprobe 查找失败时调用内置扫描，并显示明确状态提示。
- `cowmata_tailring/ui/translations.py`：补充后备状态和失败原因的英文翻译。
- `tests/test_dahua_duration.py`：覆盖帧率推导、ffprobe 缺失和复制 mtime 冲突。
- `CHANGELOG.md`：记录用户可见修复。

## 数据和兼容性影响

- 不修改视频文件，不转码，不生成视频副本。
- 后备索引继续使用现有轻量缓存格式，不额外增加大文件。
- 正常安装 ffprobe 的机器仍优先使用原完整探测流程。
- 乐橙 ffprobe 单文件超时由 120 秒收紧为 30 秒，超时后自动进入内置扫描。
- 后备扫描不会把乐橙送入不适用的通用 PTS 时间轴分支。

## 验证方法

- 用带有 50/50/100 ms PES 节奏的合成 MPEG-PS 验证平均帧间隔为 66.667 ms。
- 用不存在的 ffprobe 路径验证仍能得到时长和关键帧索引。
- 模拟 ffprobe 超时并验证自动进入内置扫描。
- 用 2.6 秒复制 mtime 验证约 20 秒完整扫描结果不会被覆盖。
- 运行完整测试和 Ruff 静态检查。
- 对 `J:\产犊\8.18-8.22 西南一牛舍\乐橙` 真实文件分别运行 ffprobe 完整探测与纯内置探测并比较结果。

- Dahua 时长定向测试：`19 passed`。
- 完整测试套件：`131 passed`。
- Ruff 静态检查：通过。

## 已知风险

帧率推导至少需要两个有效的相邻 PES 时间区间。如果录像头部和时间戳同时严重损坏，内置扫描会明确失败并保留 VLC 后备，不会伪造时长。
