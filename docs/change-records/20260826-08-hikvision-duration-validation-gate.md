# 海康未校验时长隔离

## 问题现象

切换海康 `hiv*.mp4` 录像时，进度条右侧会短暂显示 8 小时或 16 小时，随后才恢复为十几分钟的真实时长。如果首次包时间轴扫描失败，界面还可能一直保留 VLC 的异常原始时长。

本次复现文件：

`J:\行为\8.18-8.22 东一牛舍\海康\hiv00023.mp4`

实测数值：

| 项目 | 数值 |
|---|---:|
| VLC 原始时长 | `30,821,470 ms`（`08:33:41.470`） |
| 校正后的有效时长 | `1,155,872 ms`（`00:19:15.872`） |
| 中间异常 PTS 跳变 | `29,662,641 ms`（约 `08:14:22.641`） |

## 根本原因

海康录像接近末尾时存在一个很短的残留包段，其 PTS 与主画面段之间相差数小时。VLC 先按首尾 PTS 跨度报告原始时长，工具的后台 ffprobe 包扫描随后才识别并压缩这个无画面的时间戳空洞。

修改前，播放器每 50 ms 轮询一次 VLC，并把后台扫描完成前获得的原始时长直接发送给界面。因此错误值虽然只出现约半秒，仍会改变进度条比例；扫描失败时还会成为永久值。

## 修改前行为

```text
打开海康视频
  → VLC 报告 08:33:41.470
  → 界面立即显示错误时长并允许按错误比例操作
  → ffprobe 扫描完成
  → 界面改为 00:19:15.872
```

扫描失败时：

```text
ffprobe 失败 → 继续使用 VLC 原始时长
```

## 修改方案

1. 海康 MPEG-PS 文件打开后进入“时长未校验”状态。
2. 有效时间轴索引产生前，公开时长固定为 0，不发布 VLC 原始时长。
3. 校验期间 `is_seekable()` 返回 `False`，程序内部的同步定位仍可排队，待索引成功后再执行。
4. 校验成功后一次性发布包时间轴校正时长；缓存命中仍可立即使用。
5. 校验失败时暂停播放、清除待执行跳转、禁用继续播放和定位，不再回退不可信时长。
6. 接通播放器时间轴状态信号，在状态栏显示“正在校验”以及持久的失败原因提示。
7. 在线程边界捕获非预期扫描异常，确保后台任务不会静默退出并让界面永久停在“正在校验”。

修改后的首次无缓存事件顺序：

```text
0 ms → 1,155,872 ms
```

不再出现中间的 `30,821,470 ms`。

## 修改文件

- `cowmata_tailring/media/safe_engine.py`：增加海康时间轴可信状态、时长隔离、跳转保护和失败冻结。
- `cowmata_tailring/app/_layer_stable.py`：把时间轴分析状态接入应用状态栏。
- `cowmata_tailring/ui/translations.py`：增加海康校验失败提示翻译。
- `tests/test_hikvision_duration_gate.py`：覆盖未校验阻断、普通视频不受影响和失败清理。
- `CHANGELOG.md`：记录用户可见修复。

## 数据和兼容性影响

- 不修改、移动或重新封装任何源视频。
- 不生成 MKV 或视频副本。
- 继续使用原有轻量 `*.timeline.json` 缓存格式，无需清理旧缓存。
- 普通 MP4、右 1 视频和乐橙/Dahua 专用时长索引不进入本次海康阻断分支。
- 无缓存海康文件在扫描完成前暂时显示 `00:00:00.000`，进度条不可操作；本机真实文件约 0.5 秒后恢复。

## 验证方法

1. 运行新增海康时长门控测试及相关播放回归测试。
2. 运行完整 pytest 和 Ruff。
3. 为 `hiv00023.mp4` 使用独立空缓存目录，记录每一次 `duration_changed`。
4. 模拟 `find_ffmpeg()` 抛出 `FFmpegToolError`，验证失败后不发布原始时长，并拒绝播放和跳转。
5. 确认 `J:\` 源视频大小和修改时间未改变。

## 已知限制

- 海康缓存未命中时仍需要可用的 ffprobe；本修复的失败策略是明确禁用不可信时长，不是新增无 FFprobe 扫描器。
- 校验失败后需要修复 FFmpeg 路径或视频读取问题，再重新打开文件触发校验。
- 文件头损坏到无法识别为 MPEG-PS 的录像仍由打开前文件健康检查和 VLC 自身处理，不属于本次有效海康时间轴分支。
