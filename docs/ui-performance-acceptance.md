# 3.1.0a3 外观与播放性能阶段（2026-09-06）

本阶段先交付外观、八路播放负载策略与保存不卡界面的改进。后续新版事件模型与独立历史标注回看不计作本阶段已实现。原始录像、九轴 JSON、旧模型、旧交付包均保留。

## 入口与规则

- 默认布局仍为 A「大主视频＋辅视角＋底部九轴」，B 网格、C 波形画中画及 Fluent 彩色图标保留。
- 低频外观选项中可开关毛玻璃观感：缓存的柔色背景、半透明面板和 Windows 11 支持时的原生 Mica 背景。视频、波形不透明，不逐帧模糊。系统不支持时自动退回普通背景。
- 播放条可选「八路全速」或「主路优先 · 辅路预览」。实际路数仍由素材面板勾选（1–8 路），并非必须八路。默认仍保留全速，可按电脑负载切换，选择随工程保存。
- 主路优先时主画面用原片全速播放；辅画面使用宽度最多 480 像素的低频预览，最多两个后台提帧任务，公平轮换，无无界队列。预览显示其真实时间与时间差，不冒充同步实况，超过 10 秒隐藏。
- 预览不能作为当前真值证据，也不参与全路严格同步等待；点击/Alt+数字切主视角后定位到该路原片。暂停后各路恢复原片精确 PTS 帧，主视角优先读取。不能把低负载模式理解成八路同时原画全速。
- 全速模式冷启动分批交给 Qt 事件循环处理，避免一个鼠标回调里连开八个解码器。共享的备用播放器和各路播放器保持总量上限 9。
- 暂停查看八张静态图不再启动八个 VLC 解码器；由两个后台任务提取原片精确帧。布局变更不重建原生视频窗口。
- 自动保存为单任务后台顺序落盘；保持 fsync、备份、原子替换。手动保存/切换工程/关闭会先等待旧任务完成，避免旧快照覆盖新修改；保存失败拒绝关闭。

## 实测记录

验证目录：工作区的 `workspace_validation_20260906`。当前测试电脑：Windows 11、RTX 2080 Ti、24 逻辑处理器、约 128 GiB 内存。不要外推成低配置电脑保证。

高清压力样例为真实 2560×1440、约 12.5 fps 的 HEVC 牛舍画面，无重编码封装成 8 路独立测试文件，每路两段约 30 秒，循环并切换主画面及 A/B/C。它是重复真实画面的受控解码压力测试，**不是八台真实相机，也不是实际现场同步真值验证**。测试时钟仅写在隔离测试工程。

最终两种模式均为 180 秒，主画面显示帧率中位数均约 12.0 fps，并通过结束时恢复八路原片精确暂停帧的检查。内存仅为主进程运行峰值，不包括 GPU 显存和辅预览进程；CPU 计数仅含主进程，不含辅预览 FFmpeg 进程，不据此声称总 CPU 降低。

定位到的卡顿原因包括：同时启动八个解码器、每 5 秒自动保存同步刷盘、重复应用未变的 Qt 样式。逐项修复后重新测量，没有用平均帧率掩盖长停顿。第 2 轮保存回调曾达 1002 ms；后台保存后播放阶段不再出现该回调阻塞。

- `stress_hd_balanced_02.json`：主画面显示帧率中位数 12.0 fps，1050 个辅预览请求、1039 个完成、11 个过期丢弃、0 个识别/提帧错误；最大同时任务 2；最后暂停的 8 路全部有原片精确 PTS 证据。
- `glass_handoff_01.json`：实际原生 VLC 八路小视频跨文件、九轴已校准续接、未校准提示且不强行加载、参考时间不倒退全部通过；播放中切换 6 次布局，播放器对象、句柄、参考时刻、seek 代数不变。
- `ui_performance_pytest.xml`：289 项回归通过，含后台保存有界/顺序/失败恢复/拒绝关闭、预览不进入真值、过期回调不污染画面、旧测试事件循环隔离。
- `ui_glass_02`：真实九轴和真实双路录像 A/B/C、小屏幕与全高清控件截图；未伪造九轴同步；修复过的状态栏背景已截图复核。
- `glass_150dpi.xml`：150% 缩放独立进程，29 项布局、输入、毛玻璃回退、播放策略和保存安全测试通过。
- `glass_original_ps_8.json`：直接从真实监控 PS 原片的索引启动，启用无重编码兼容缓存，8 个独立解码器约 4 秒全部就绪；45 秒试验中，10 秒后所有采样均为 8 路就绪，并检查各路实际显示帧计数持续增加。重复原片仅用于解码测试，不冒充 8 台相机。

## 边界

本版仍是 alpha 验证版，不承诺任意电脑、任意编码、八路 4 倍速或连续几天零卡顿。八路全速仍有数百毫秒的切换/重新定位延迟。海康 PS 容器可能需要「兼容缓存」改善随机跳转：仅无重编码封装，原片不动，精确暂停仍回原片。测试日志中的 VLC 时间戳转换警告有恢复出帧记录，未据警告消失与否判断通过。
