# 数据整理与数据类别

3.3.0 的标准流程是先整理数据，再标注保存，最后复核导出。入口为顶部「数据整理」，包含数据审查、数据归类和异常报告。子窗口可以独立打开、隐藏；后台任务不依赖窗口保持显示。

## 使用

1. 先选目标数据工程，添加来源。九轴可选单份 JSON、多个文件或嵌套目录；录像可选单个文件、多文件或每一路的根目录，逐路指定视角01～视角08。
2. 先审查。审查原始九轴结构、空文件、临时文件、文件占用；扫描视频文件信息，不进行全量解码、OCR 或完整哈希。视频能否解码和准确时间仍由播放器核验。
3. 归类前填写已确认的采集日期：单日只需起始日期，多日填写结束日期。选择本批数据类别，未知类别不默认猜为正常健康。不同类别分批整理。
4. 预览来源与目标，核对异常，点击「执行剪切归类」。重名原件进入带序号的日期批次，不覆盖、不拼接。
5. 同目录或存在父子关系的标注工程必须先「保存并暂停当前工程」。其他目录可继续标注。中断后用「继续上次整理任务」，也可载入任务记录中的 plan.json 续接。

## 输出结构

    数据工程/
      九轴/546C50CA07D5-21100-10/2026-08-03/原文件.json
      九轴/546C50CA07D5-23381-w1/2026-08-07/原文件.json
      视角01/2026-08-03/原视频.mp4
      视角02/2026-08-03至2026-08-07/原视频.mp4
      ...
      视角08/
      绑定.csv
      实验佩戴记录.csv
      整理清单.csv
      数据分类.csv

只保留必要的设备、视角、日期层级，来源的下载目录、相机导出目录等嵌套层级不会复制到目标。重名批次示例为 2026-08-03_001。移动后仅移除来源下已为空的子目录；不递归删除原件。

视角目录只放视频，九轴日期目录只放原始九轴。非素材、系统临时文件和空文件按预览移到工程外的「整理隔离/任务号」；已有标签、配套绑定/实验/分类表、无法确认的异常九轴继续保留。隔离也是移动，不额外复制素材。已整理工程可使用「预览规范视角名称」去掉厂商名称，保留既有日期批次、素材身份和校准/标签坐标。

## 九轴目录与设备复用

设备目录为“完整12位十六进制设备编号-数字牛耳标号-现场记号”。牛耳标前导零保留；记号支持数字、大小写字母及其组合，大小写不互换。例如 `546C50CA07D5-21100-10`、`546C50CA01F1-23381-w1`。现场连续编号继续用 10、11 也有效，不必耗尽 0～9 后切换字母。

来源选择后先检查目录。缺分隔符、颠倒字段、只有设备后四位或 JSON 设备号不符时，显示具体问题和候选名称，阻止新整理执行；不自动猜牛号或改名。短号仅在该目录 JSON 提供唯一匹配全号时给出建议。命名异常的有效九轴保留，不进入杂项隔离。

同设备在不同日期清洗复用是正常情况。身份随每份原始记录及真实采集日期保存；不同牛、不同日期不会因为设备号相同而去重。已有标注若与目录身份冲突，保留人工内容并提示复核；不会用目录推断覆盖既有牛号。

九轴使用原始采集日期建目录，不把多日记录强行放进一个时段目录。视频没有已核验采集时间时按用户确认的单日/时段归档；归档日期不代替画面时间校验。

## 类别与行为独立

| 数据类别 | 保存代码 |
| --- | --- |
| 正常健康 | healthy |
| 发情 | estrus |
| 孕早期 | pregnancy_early |
| 孕中期 | pregnancy_mid |
| 孕晚期 | pregnancy_late |
| 产犊 | calving |
| 疫病 | disease |

类别是用户确认的采集分组，不是自动诊断或行为事件。七类数据均可标注起立、卧倒、抬尾、甩尾、排尿、排便，也保留工具已有的其他行为。参加某类实验不自动生成该类事件或正负样本。

「数据分类.csv」按每个素材相对路径保存类别、日期、批次任务号和说明；同一工程中的新批次不会覆盖其他记录的类别。工程自动保存、完整/片段标注 JSON、事件 CSV、逐样本 CSV、训练元数据均保留：

    {"dataset_category": "estrus", "dataset_category_label": "发情"}

旧记录没有类别时显示「数据类别：未设置」，可在左侧牛号下补选，也可更正已有记录；修改随标注保存，行为标签与原始时间坐标保持独立。更正仅针对当前记录，不替其他记录猜类别。BORIS 保留原有六列并追加类别与身份列；完整/片段 JSON、事件及逐样本 CSV、训练元数据与团队回传均携带逐记录身份。

## 速度与恢复

大目录审查、JSON 解析、文件移动和索引在一个独立 QProcess 中执行，Windows 后台进程使用较低优先级，进度消息节流。单次只解析一份九轴，不把整批数据或视频读入内存。

Windows 同卷使用不覆盖目标的 rename；跨卷直接拦截，不退回复制后删除。微软文档说明跨卷 MoveFileEx 在允许复制时会执行 CopyFile + DeleteFile，因此不能承诺跨盘瞬间剪切：[MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)、[Python os.rename](https://docs.python.org/3/library/os.html#os.rename)。

移动前后核对文件卷号、文件 ID、大小和修改时间，完整 SHA256 未计算时清单留空，不伪造哈希。每步保存意图、完成记录；中断任务继续时核对文件身份并跳过已完成项，修复被强制关闭截断的日志尾部。未完成任务保护相关目录，防止标注读到半整理的数据。

任务记录存放于本机 LocalAppData 下的 COWMATA Annotator/organization-tasks，目录占用记录也位于软件数据目录。数据资源下面不会堆积后台任务文件。界面线程不执行批量扫描；Qt 线程约束见 [QThread 文档](https://doc.qt.io/qt-6/qthread.html)。

## 验证范围

用户提供的真实工程仅做只读审查和播放验证，未移动、复制或改写真实素材：366 份九轴、842 个视频、3 张配套表。结构审查未发现空素材或九轴结构异常，不等同于逐个验证录像解码。

3.3 的合成文件移动、旧索引迁移、命名异常拦截、跨日期设备复用、七类保存导出与 GUI 交互结果见 [功能实测](release-330-validation.md)。原始客户失败数据位于客户电脑，本机使用对应结构复现；不能把本机通过当作客户原件已验收。
