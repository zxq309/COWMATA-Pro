# a5：完整记录随标签与五类候选

## 用户入口

- `更多 → 标注 → 新版事件候选预测`。完整 V2 九轴、人工确认牛号后，选版本/单事件或顺序五类扫描。双击候选定位；手工拖选真实范围后建视频草稿，原有真值门控不绕过。
- `更多 → 工程 → 导出当前成果`：单个 JSON、格式 v2，原始九轴 JSON 字节完整内置且 SHA-256 校验。原父记录坐标、牛号、校准/历史版本、模型来源和相关视频身份/时间快照同行。片段格式 v1 仍只嵌入原始九轴帧；a4 引用式文件与旧工程继续可读。

## 模型与运行库

五份算法/模型从用户 `事件识别20260906/01_算法` 原样复制到 `assets/event_models/20260906`。`pack.json` 逐文件记录 SHA-256，加载前检查。源算法、阈值、特征提取和质量门不修改；不读取训练标签，不训练。

GUI 使用现代私有 Python 3.13；五个旧序列化模型在 `model_runtime_20260906` 的 Python 3.8.10 中运行，主要依赖与用户参考环境相同，完整版本见 `requirements-events-20260906.txt`。Python 3.8 已停止维护，因此只用于受控本地离线推理；这不是可运行任意用户 pickle 的安全沙箱。切勿加载未经审查的模型包。

用户无需安装 Python、Conda、pip、科学计算库或模型，也不调用系统 Python。后台单任务、Windows 最多两个逻辑 CPU、低于正常进程优先级、可取消；记录/牛号/工程改变时旧结果不写入。缓存按完整来源身份、牛号、模型包 hash 和适配器版本定位；人工审核状态另存于成果中。缓存不是标签真值。

实际压力测试发现全速八路与持续推理叠加时可能产生长停顿，因此后台推理期间四路及以上的播放会自动启用主路优先保护（主工作台和独立历史回看共用负载状态）。下拉框同步显示有效策略；任务结束不自动跳回全速以免来回抖动，可手动恢复。暂停仍检查每路原片精确帧，辅路预览不作真值。

模型时间字段映射：起立/抬尾 `spot_s`，卧倒 `around_s`（原算法已取约 5 秒），排尿 `event_time_s`，甩尾 `center_s`。只换算父记录内毫秒；不使用 `create_time` 推导出的模型绝对时刻，也不把窗口 `end_s` 当作真实动作结束。

## 验证范围

- 三份真实完整九轴（正常记录和异常硬件记录），五类共十五组，对照用户 Anaconda 3.8.8 原 CLI：候选数、相对点、分数及逐候选质量字段一致。原始九轴与原模型 SHA-256 不变。该测试是工程兼容性，不是独立泛化准确率评估。
- 单文件完整记录/片段导出、脱离原目录回看、重名与内容改变拒配、版本兼容、来源变更及取消、模型候选与真值隔离纳入自动回归测试。
- 包内解释器在移除外部工具 PATH、阻断 Python 网络条件下测试 Qt/OCR/原始录像/九轴/五模型。打包后还需实际 BAT 启动及原生多视角播放测试。详细实测数量和指标以本次交付验收记录为准，不承诺所有机器八路原分辨率零卡顿。

## 后续算法迭代（维护者，不是新用户配置步骤）

1. 保留旧版本目录，复制经审查的新 CLI/模型到新的日期版本。保持输入为完整原始 V2 和输出为相对时间候选 CSV；若参数/输出结构变化，新增明确的适配器并测试，不能仅替换 pickle。
2. 调整维护工具 `scripts/register_event_pack.py` 中对应契约，生成新目录的 `pack.json`。当前 `csv-points-v1` 和 `model_runtime_20260906` 只适用于这套兼容依赖。需要新依赖时另做隔离运行库契约，不升级旧环境破坏历史模型。
3. 对照参考 CLI 运行 `scripts/verify_event_models.py`，做正常/异常输入及取消/播放负载回归，构建新便携包。注册并不等于模型经过科学验证。
4. GUI 版本选择自动列出软件资产目录中的兼容版本。旧候选保留来源及模型 hash，重新预测不会升级为真值；旧单视频/旧模型辅助入口仍保留。

## 明确限制

只提供完整 V2 的五类候选推理；不将片段补成假完整记录，不把分数当概率，不把空候选或质量拒绝当负样本。未同步可先看波形/候选，但录像位置不凭服务器时间猜。缺失录像、同步外推或无法确认牛号时不能生成确认真值。原件录像始终不内嵌、不切割、不重命名；独立回看仍需能访问实际录像。
