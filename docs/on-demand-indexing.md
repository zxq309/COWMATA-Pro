# 3.1.2 按需加载与逐份标注（2026-09-09）

本次仅改标注工具，不执行旧标签迁移或原始数据整理。

## 使用

1. 「文件 → 打开数据工程」。程序轻量清点目录，不立即读取全部 JSON 或 OCR 全部录像。
2. 鼠标悬停「素材」展开列表；点击可固定，Ctrl+L 也可固定/收起。在设备下选一份九轴，支持搜索文件名。
3. 已有未完成进度时恢复原位置。没有未完成的当前记录时选择该设备下一份未完成记录；全完成时不打开录像。切换其他设备仍由列表完成。
4. 按 JSON 内的采集时间和实际时长找多视角录像，优先保留人工同步关系。查询两端各留 30 秒浏览余量，不改标签坐标；跨越起点/终点的小视频均为候选。
5. 核对牛号、同步和画面后标注。「完成本份」提供已完成下一份、已完成保存退出、没做完暂存退出、继续本份。到记录末尾会提示一次，不因一条标签就自动认定整份完成。
6. 原 JSON、录像不改写。进度、同步、标签、时间缓存仍在现有「标注工程」内；拷贝工程时保留它。

## 首次检索与缓存

文件清点只核对路径及文件属性。普通重开不会读取所有录像内容。

先读取已支持录像的内部录制时间，小范围预读不需启动 OCR 模型；未知格式才用 OCR 路由线索。两类线索存入 index.sqlite 的 video_hints 表，绑定相对路径及文件状态；它不是文件身份或真值。命中候选才做完整 SHA-256、包时间轴及独立图像核验。内部时钟候选可以先播放复核，不必等 OCR 全部结束；未经图像确认不能变成已核验区间。见 [原生时间说明](native-video-timing.md)。

同一父目录作为一次内存卡批次，编号自然顺序只帮助缩小搜索范围，不证明录像连续或时钟正确。时钟跳变、识别失败、乱序、缺口保留未确认状态。

默认最多探索 48 个非定向 OCR 位置；原生时间预读、已经有边界线索的定向搜索继续完成，不被这个探索额度截断。尚无足够线索时用「工具 → 录像索引 → 继续扩大当前时段检索」。也可主动选择「后台完整索引」或暂停。其他未查录像存在时，绝不会据此宣布后续无视频真值。

不能承诺第一次面对任意乱序、无时间文件名的大量录像能瞬间完整定位：至少需要读取时间线索；未知格式还需要抽取画面。难读的时间戳可能进入多次核验，仍会耗时；再次访问未变文件可复用结果。哈希解决内容身份，不会凭空产生录制时间。

Windows 当前文件可立即尝试读取，不再机械等待三秒；前后检查文件写入占用与状态，复制中仍拒绝加载。已解析的同一份九轴直接交给界面，避免重复解析。文件新增/删除由目录监视和定期轻量扫描发现，原始数据不改写。

## 完成与恢复

project.json 的 review_progress 保存每份记录路径、文件状态、SHA-256 身份、完成状态与位置；单份 annotations 文件仍保留完整人工成果。

旧版已经保存过的工作会显示进行中。旧版没有明确的整份完成标记，不能由“已有标签”推断完全检查结束。改名/移动后会重新核验身份；同名文件被替换不能继承旧完成状态。

## 界面与资源

菜单沿用文件、编辑、视图、工具、帮助；常用播放与标注保留直接入口。解释放在悬停提示中，缺失/未核验等重要状态不隐藏。设置、列表勾选有可见对勾，下拉框有箭头，磨砂背景不处理视频帧。

新工程默认「单路优先」：先准备主路，其他视角逐个加载静止图；点击画面内播放控件切换唯一播放视角。静止图带时间、不会冒充当前实况；暂停后各路依次对齐原片。可选择「流畅优先」周期预览或「多路全速」。原有工程保留自己保存的播放偏好。更新入口在「帮助 → 关于」，原有自动提醒仍工作。

播放时，当前时间窗的定向检索/候选核验继续在低优先级后台执行，避免下一片索引被播放永久饿死；无关的全量探索仍让出资源。原片首轮识别速度、硬盘带宽和解码能力仍可能导致等待，不承诺所有电脑零卡顿。
