# 3.9.7 保留视频码流与曲线修订验证

## 改动与范围

兼容的 8 bit 4:2:0 H.264 / H.265 整段录像优先复制视频码流并封装为 MP4，H.265 使用 hvc1 标记。PCM 音频转换为 AAC；“无损”指视频码流，不能声称音频无损。中段精确裁切、格式不兼容或封装校验失败仍走既有编码回退。全范围摄像头保留原像素范围、原分辨率和编码；录像机校时证据及传感器同步待核对提示保留。

DOCX 中五项显示问题合并处理：九轴每轴保留可读高度，空间不足时滚动；日期时间输入框明确显示边界；九轴、PPG、温度页签突出当前选择，状态栏显示当前类型；记录列表标明九轴或 PPG；旧纯设备号目录和日期目录中的 PPG 按实际设备、牛号证据及重叠采样时段查看。没有重叠采样时明确显示真实缺口，不伪造连续数据。未确认牛号的旧目录兼容仅用于曲线浏览，不授予牛号绑定或自动共享标签的权限。

## 完整性与播放证据

真实 HEVC 测试夹具保留全部 75 帧，解码后逐帧像素 MD5 与源一致；模拟已证实的录像机时钟回拨后，输出时间线连续。对比试验中，将真实 HEVC 片段第 36 帧部分切片清零：CPU 严格解码报错，QSV 却返回成功和 75 帧。因此生产完整校验继续使用严格 CPU 解码，硬解码不作为唯一完整性凭据。通过解码不等于能证明任意位翻转均未发生，原始文件与归档哈希仍用于来源一致性核查。

Computer Use 已在实际 StableMediaEngine / VLC 的八画面验收副本中播放同一长录像，点击播放、跳至 30 分钟、跳至接近片尾，八画面均出现对应新画面并播放到结尾。此为同片八播放器验证，不等于八路不同原盘同时转码基准。记录的 seek 调用返回时间不作为画面精确定位延迟宣称。

获得用户继续授权后，Computer Use 补测完成：真实九轴在波形布局逐轴可读；实际 PPG 主记录自动选择 PPG 页签并显示主通道、红外两条曲线；返回九轴页签不混入 PPG；温度页签突出当前选择并保留实际时段缺口。输入 2026-09-05 00:06:40 后点击跳转，游标正确定位。该真实样本的温度与主记录时段不重叠，因此温度有值分支以自动化用例验证，不宣称此样本出现了温度曲线。可见验收期间 50 ms 心跳 P99 约 66 ms，最大观测约 148 ms；不作所有数据量的不卡顿承诺。自动化测试涵盖曲线最小高度、PPG 主记录类型、旧设备目录/平铺日期目录、同设备身份冲突隔离及真实时段缺口。

## 官方参考与采用理由

- [FFmpeg streamcopy](https://www.ffmpeg.org/ffmpeg.html)：兼容媒体复制压缩包而不解码重编码，是减少计算和避免二次损失的基础。
- [FFmpeg setts](https://ffmpeg.org/ffmpeg-bitstream-filters.html#setts)：仅对已验证连续帧计数的来源重建包时间，不用猜测抹平真实缺口。
- [Adobe Smart Rendering](https://helpx.adobe.com/uk/premiere/desktop/render-and-export/render-sequences-for-playback/smart-rendering-supported-formats.html)：参考匹配格式避免不必要重压缩的设计原则；不据此宣称 Adobe 支持本项目的 DAV 格式。
- [Apple HEVC](https://support.apple.com/en-ca/116944) 与 [hvc1 编码标记说明](https://developer.apple.com/documentation/http-live-streaming/hls-authoring-specification-for-apple-devices-appendixes)：保留高效编码并使用明确兼容标记；实际兼容性以本程序播放器验收为准。
- [Intel VPL](https://www.intel.com/content/www/us/en/developer/tools/vpl/overview.html)：硬件路径用于受支持格式的回退处理；厂商支持并不替代本机保真及损坏样本验证。
