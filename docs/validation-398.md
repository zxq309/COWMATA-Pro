# 3.9.8 原始录像与续跑验证

日期：2026-09-19。工作源码基于 3.9.7 / 3.9.8 在制版本；以下仅报告实际完成的检查。

## 报错样本与修复

从用户实际任务中只读提取视角01失败的一小时录像，原文件 1,424,999,084 字节。原任务记录转换失败耗时 1,957.787 秒，错误为 AAC 非单调 DTS / MP4 mux -22。mono 声道猜测和像素格式提示不是此失败的直接原因。

原片为 HEVC 2560×1440，89,987 帧，原生时长 3,599.580 秒。逐包检查证实视频、PCM 音频帧序号连续。视频主要间隔 40 ms，实际存在 20、80、100 ms 间隔，均保留原始计数；音频初始偏移 10 ms，PCM 样本时钟与包计数最大差异 170 ms，低于该来源的 200 ms 界限，写入时钟证据。不是所有损坏的原片均可如此修复。

| 检查 | 结果 |
| --- | --- |
| 从录像机原盘提取 | 28.581 秒 |
| MP4 封装与运行时校验 | 18.249 秒，不含原盘提取 |
| 原始计数分析 | 0.516 秒 |
| 输出大小 | 1,427,870,382 字节，保留 HEVC |
| 所有视频画面码流哈希 | 原片与输出一致，89,987 个 picture NAL |
| 原生视频时间戳 | 89,987 帧逐帧完全一致，精度 1 ms |
| 输出音频 DTS | 168,727 个 AAC 包严格递增 |
| 额外独立整段解码 | 成功，0 丢帧、0 重复、错误输出为空 |

画面码流 SHA-256：

`aa78e647a3b2413211f94c30dcb866927ddcc07c543e45cd8746777985735c6f`

整段解码验收额外耗时约 169 秒，仅作为本次独立质量验收，不计入 18.249 秒的运行流程。不能把 18.249 秒当作从原盘到最终归档的总耗时。音频时钟修复有上述已记录误差边界，不宣称零音画误差。

FFmpeg 对 DHAV 的日历时间与 16 位计数处理依据：[FFmpeg 官方 dhav.c](https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/dhav.c)。产品只对可验证的源帧连续性应用修复，无法证明的缺包和时间跳变仍提示核对。

## Computer Use

- 通过真实界面扫描从该录像截出的 20 路 30 秒样本；20 个视角正确匹配并归档，现场可见两路同时处理，队列状态真实显示。此项验证功能与界面，不代表 20 路长片并发吞吐。
- 再次点击“继续上次归类”：20 个成品 0.332 秒完成复用，所有成品修改时间未变化。
- 原片并行批次约 14 秒完成。50 ms 界面心跳的 99 分位约 66 ms；最大观察间隔约 623 ms 包括窗口最大化/启动阶段，未出现 Windows 未响应。不能据此承诺任何机器或大批次完全无停顿。
- 派包界面直接选择真实“产犊”子目录后点击扫描，能定位牧场根目录并列出实际日期和可派数量；没有生成测试派包到真实牧场。
- 真实暂停按钮点击前短片批次已结束，因此不把该点击算作暂停测试；中断后恢复、落盘后回执前中断、目标变更及占用保护由自动回归覆盖。

## 自动回归

最终结果写入交付目录的验证报告。包括原生视频间隔、音频缺包拒绝、整片不按错误时钟截断、缺一帧即拒绝、已完成文件不重新读取、保存状态后一键继续、崩溃中断恢复和变更/目录锁保护。

## 边界

- 常规成品 MP4 同盘移动与原盘录像封装不是同一成本。单硬盘并发寻道可能更慢，实际处理路数受资源预算限制。
- 缺失/变化的已完成成品不会被悄悄覆盖；需要核对后再处理。已归档且未变化的成品始终保留。
- 已完成任务复用速度不计为磁盘传输带宽。
- 验收与测速文件保存在开发工作目录，不加入用户牧场原始数据，也不进入纯净发行包。

最终全量回归：1,857 项通过、7 项跳过，耗时 128.93 秒；Ruff 全部通过。
