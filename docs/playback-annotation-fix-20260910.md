# 播放与动作标注修复（2026-09-10）

本次针对 3.3.0 客户反馈修复播放等待、动作起止入口及候选回看，保留现有数据整理、身份规则、分类和成果格式。

## 操作

1. 选择行为，点击“开始…”记录起点；动作结束后点击“结束…”。同一数字键也可记录起止。进行中动作会显示名称、起点和结束键。
2. 需要放弃尚未结束的动作，点击“取消本次动作…”并确认。已经保存的标签和草稿保留。
3. 打开“标注列表”，选中视频草稿，点击“九轴起止微调”，分别拖动左、右边界。
4. 点击“编辑起止”，起点和终点可分别 ±0.1 秒或直接输入时间戳。调整后回看画面、补充证据，再确认真值。

数字键在行为下拉框取得焦点时也可使用；在牛号、时间等输入框内仍用于正常输入。

旧版已有九轴标签拖边和输入微调功能；本次将视频草稿接入该流程，并把入口直接放到标注列表。

## 原因与修复

| 反馈 | 核对结果 | 修复 |
| --- | --- | --- |
| 暂停有画面，播放长时间黑屏 | 暂停读取原片精确帧；播放准备兼容封装。部分监控音轨采样率缺失导致 Matroska 写头失败 | 仅针对该音轨错误重试视频流复制；健康音轨保留，异常音轨只在缓存中跳过并提示 |
| 播放、拖动反复等待 | 原来定位变化会取消整段准备；兼容缓存长锁还可能阻塞界面查询 | 首张暂停帧出来后后台准备，播放与连续拖动共享一个任务；完成后只使用最新目标；拆开构建锁与短时索引锁 |
| 按键、按钮似乎无效 | 录屏已进入动作保护分支，但正在记录的标签提示被隐藏；行为下拉框也会吞数字键 | 持续显示当前动作；主按钮结束实际正在记录的动作，换数字键时明确提示；增加可确认取消入口 |
| 卧倒候选回看失败 | 候选回看使用公共播放器，截图错误来自兼容封装，不是卧倒预测结果 | 公共播放通路统一处理，适用于起立、卧倒、排尿、抬尾、甩尾候选回看 |

缓存仍需核验时间连续性、时长、起始 PTS。其它无法准备缓存的错误会尝试原片 1×播放，暂停后再次播放可重试；不会把旧画面当作已定位的新帧。

## Windows 实测

读取用户提供的 2026-08-03 至 08-07 数据工程中的视角02/mb00145.mp4：256 MiB、约 23 分49秒、H.264/MPEG-PS。测试文件 SHA256 和文件状态前后未变化。

| 项目 | 本机结果 |
| --- | --- |
| 暂停原片首帧 | 0.515 秒 |
| 首次后台封装 | 1.165 秒；连续前后跳转共用一次构建 |
| 缓存播放 1× / 2× / 4× | 实测时钟速率 0.987× / 1.963× / 4.014×，显示帧持续增加 |
| 缓存大段前跳 / 后跳 | 0.118 / 0.117 秒 |
| 缓存暂停后续播 | 0.119 秒；独立预备流程复测为 0.127 秒 |

首次直接点击播放的独立空缓存测试为 2.811 秒，包含封装和定位。以上没有清空操作系统磁盘缓存，不能推定所有客户硬盘都有相同速度。直接走监控原生流的倍速已复现失准，因此保留经过验证的封装播放。

异常音轨另用真实 MPEG-PS 测试文件复现：原 FFmpeg 命令报出与截图相同的 sample rate not set。修复后视频所有 75 帧的解码 MD5 与原件一致，源文件 SHA256 不变；实际播放、暂停回看、续播通过。用户提供的八月样本没有该异常音轨，九月客户原工程尚未在本机复现。

动作流程覆盖真实 Qt 鼠标拖动、两端独立调整、取消确认、非零时钟映射、撤销重做、保存重开及跨记录保护。视频草稿预览使用临时负 ID，不写入已确认事件；修改时间后清除旧证据，保留人工复核要求。
