# 第二阶段界面提案（A 默认已确认，尚未替换现有界面）

目标是“加载九轴 → 看同一时刻的牛 → 记录动作 → 核对同步 → 确认真值”。
界面不要迫使标注者先从九轴波形猜事件。第一阶段仅改算法、续接和安全提示，视觉改造独立验收。

## 三种可切换的工作区

| 预设 | 空间分配 | 用途 |
|---|---|---|
| A 观察优先（建议默认） | 上方大主视角＋可收起的辅视角列；下方九轴约 25–30%；独立薄标签轨道 | 长时间看牛、随看随标 |
| B 多视角对照 | 自选 1–8 路，2×2、2×3、2×4 等网格；下方共享九轴与标签轨道 | 当前视角遮挡，直接比较其他视角 |
| C 波形精修 | 波形占主体，主视频画中画；辅助视频按需展开；标签独立轨道 | 精修动作起止、复核边界 |

三种预设是同一套播放器和同一参考时刻的布局，不是三个独立播放任务。切布局不重新打开视频，不重置倍率、位置或同步。

默认 A 的层次：

```text
┌ 工程／设备／牛号 ───────── 布局选择 · 搜索 · 更多 ┐
│                                                │
│           主视角（大画面）          辅视角缩略列 │
│                                                │
├ 播放／逐帧／倍率 ───── 参考时间 ─── 同步状态 ─────┤
│ 九轴波形：加速度／角速度／磁场按组开关；悬停读数 │
├ 独立标签轨道：动作区间、点事件、待复核状态 ──────┤
│ 常用标签快捷键 · 开始/结束 · 撤销 · 确认真值      │
└ 索引进度／覆盖状态（有异常才展开说明）───────────┘
```

左侧设备/记录树平时收起；右侧“所选标注详情”选中时才展开。
详细索引表、完整标签表、OCR 模型信息、批次导入、时钟高级设置收进菜单/抽屉。
关键的“同步未确认／无录像／原文件变化／未保存”不能藏进菜单。

## 操作细节

- 视频标题条仅保留视角名、可见状态、放大和更多。双击单路放大，再次双击恢复；Alt+1…8 切主视角，参考时间不变。
- 1–8 路按实际需要勾选，不默认让八路高清全部解码。保留硬件解码、严格同步开关和原片兼容缓存。
- 一套全局播放控件；主视角发声，其余静音。画中画和网格只是显示模式，不创建无限数量的播放器。
- 九轴值悬停后显示，保留通道名、单位和时间轴。真实间隙不连线填平，显示抽稀不改变用于标注/导出的原始样本。
- 标签与九轴绘图分区，时间轴联动。常用标签支持少量固定快捷键＋下拉列表；复杂编辑放在选中标签的详情中。
- “看不清／未观察到”独立于“正常／无事件”。没有录像不是阴性样本，算法候选也不是人工真值。
- 九轴自动续接仍按已确认规则：同设备、同牛号、下一份有覆盖当前时刻的校准；未校准持续提示，不回退视频，也不拼造时间。
- 对话框/抽屉最多两层，给键盘焦点明显边框。输入文字时，不触发播放和标注快捷键。
- 倍率、布局、通道显隐和视角偏好按设备保存；绝对时间与原始相对时间明确区分。

## 视觉与实现

采用 Qt Widgets＋QSS＋本地 SVG 图标；不是浏览器 CSS，也不为换皮另加一套 Web 视频运行时。
QSS 的语法受 CSS 启发，但适用范围是 Qt 控件。[Qt 官方说明](https://doc.qt.io/qt-6/stylesheet.html)

参照 [Windows 设计指南](https://learn.microsoft.com/en-us/windows/apps/design/)：
使用有层次的中性背景、适量圆角、清晰焦点与一致间距；奶牛健康监测的品牌强调色建议深青绿。
先做浅色主题和深色主题，不在视频或波形下面加花纹、模糊与大面积透明。半透明仅限可选侧栏，并提供不透明回退。
不承诺所有 Windows/显卡组合都支持原生 Mica 材质。

基础图标选微软 [Fluent System Icons](https://github.com/microsoft/fluentui-system-icons)，保留 [MIT 许可](https://github.com/microsoft/fluentui-system-icons/blob/main/LICENSE)，下载后随包离线使用。
本阶段只核验来源；下一阶段定稿后下载实际选用图标，不从任意图片站拼凑未知授权素材。

## 开源项目可以借鉴什么

| 项目 | 有用的设计 | 本工具采用的边界 |
|---|---|---|
| BORIS | 点事件/持续状态、行为目录、快捷键标记与回看 | 借鉴交互，不直接搬 GPL 代码；保留现有证据确认门控 |
| ELAN（MPI） | 多层标签轨道、同步模式、选区回放 | 标签轨道与波形分离；复杂语言学层级不引入主界面 |
| mad-gui | 传感器与视频同步、添加/编辑模式、算法与导入器分离 | 维持现有 Qt6/便携播放器；不整包替换为其旧运行环境 |

来源：[BORIS 编码](https://www.boris.unito.it/user_guide/coding/)、[回放](https://www.boris.unito.it/user_guide/playback_menu/)、[mad-gui 官方仓库](https://github.com/mad-lab-fau/mad-gui)。
你提供的 [leanprover/elan](https://github.com/leanprover/elan) 是 Lean 工具链管理器，不是视频标注工具。
相关的是 [MPI ELAN](https://archive.mpi.nl/tla/elan)；其 [公开手册](https://www.mpi.nl/corpus/html/elan/) 可用于核对层轨道/同步设计，该手册本身是 6.3 版旧文档，不能据此声称是最新发行版。

## 分步验收

1. 用户已确认 A 为默认、B/C 为预设。先做真实控件原型与截图，不改证据/时间算法。
2. 检查 1280×800、1920×1080 与 125%/150%/200% 缩放下的布局、中文截断、快捷键、悬停和可读性。
3. 接回播放器，重复多路/切布局/跨片/九轴续接/逐帧测试；记录就绪延迟、帧显示、内存和句柄，不能只看主时钟在走。
4. 保存、撤销、恢复工程、源文件增删、导出真值与离线移动包重新回归。
5. 再用更多真实相机、长时录像和完整工程抽样；目前五份原片不能代表所有监控型号。

本提案不是“界面已经做好”的交付声明。默认布局已确认，真实界面样稿仍需另行核对。
