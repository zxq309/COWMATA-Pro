# COWMATA Pro 3.9.7

原始录像每完成一段，就在校验后归档到牧场共享录像目录。新增任务耗时和最终结果表，减少 C 盘暂存、重复搬运和重复转码。

## 使用变化

- 保存位置明确显示为实际的“牧场根目录／录像／日期／视角01–20／时间戳.mp4”；“打开归类目录”进入同一位置。
- 原始码流转换在目标盘的任务专属缓存中完成。校验成功后同盘重命名提交，立即可见，不再等整个批次完成才拷贝。未完成视频不会冒充成品。
- C 盘只保留任务清单和运行记录。恢复旧任务时，逐段校验并迁移该任务的旧缓存；已经转码好的文件可复用。旧任务中尚未轮到的缓存会暂时保留，避免丢失进度。
- 增加“运行记录”“耗时明细”“归档结果”。显示读取、转换、校验、归档、总耗时、文件大小和处理方式；记录自动保存为 CSV/JSON。
- 兼容的 H.264 优先快速封装。需要转码时实际探测 Intel / NVIDIA 硬件编码器，失败自动回退 CPU；维持 H.264、原分辨率、时间戳和完整解码校验。
- 暂停保留成品与当前任务；续跑核验已归档文件后复用。修复落盘与记录写入之间中断导致的重复转码。
- 已知录像机原盘直接复核同一设备，避免每段反复枚举所有磁盘。大批量表格分批刷新，减少主线程停顿。

## 速度边界

本机同一段 60 秒、2560×1440 的真实 H.265 录像，转码与完整校验合计从 CPU 的 19.682 秒降至 Intel 硬件编码的 14.737 秒，减少约 25%。硬件成品更大；该样本画面 SSIM 比 CPU 基线略高。两段 180 秒实际界面任务验证了逐段归档、暂停续跑及目标目录，详情见 [验证记录](validation-397.md)。

速度仍取决于原片编码、录像时长、磁盘和可用硬件。这里的录像转换速度不等同于普通 MP4 文件移动速度，不承诺任意 2,000 个视频都在 8 小时完成。

本版修改限于原始录像准备、进度显示和交付版本信息。常规归类、传感器下载、标签与算法沿用现有逻辑。正式原盘和原始录像保持只读。

本地提供安装包、便携包及纯净源码包；GitHub Release 仅附安装包。


同版本修订：修复暂停录像任务后重新扫描造成新旧任务冲突的问题。相同来源、范围与映射自动继续原任务；恢复按钮按当前牧场查找实际未完成任务，不再被最后一次扫描覆盖。来源变化或并发占用仍会阻止混写。
