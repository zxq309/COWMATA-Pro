# Connection component

connection_key is a newly generated, intentionally distributable transport identity, not an application login or administrator credential. The corresponding server authorized_keys entry uses restrict and a forced connection_receiver.py command. The forced endpoint fails closed unless application security is enabled. It provides no shell, SFTP, forwarding, or operating-system login. Administrator login requires an account and password. First-time operator activation additionally requires a one-time code; subsequent manual login verifies the password and the previously activated device. Business requests require an active authorized session; administrator APIs additionally require the unique owner identity. Password saving and automatic login default to off. Saved passwords use Windows DPAPI, and automatic login requires explicit user selection. Existing SSH identities and host private keys are never bundled. Server authenticity is pinned by known_hosts. Each Windows user receives a local copy with SSH-compatible file permissions automatically. Users do not import connection profiles.
